# 評価基準

学術的な新規性ではなく、**広告実務に効くか**で採点する。査読者ではなく発注者の目で読む。

## 採点軸

| 軸 | 配点 | 何を見るか |
|----|------|-----------|
| 業務接続度 | 0-3（×2） | 調査／戦略／クリエイティブ／運用／レポートのどの工程に、どの指標（CTR・CVR・CPA・ブランドリフト・制作工数）で効くか。工程と指標の両方が言えて3点。工程は言えるが指標が言えない=2点。「面白い」だけ=0点 |
| 差分性 | 0-3（×2） | `state/known-topics.md` の既知に対する差分。新しい問い=3点／既知の問いへの新しい答え=2点／既知手法のスケール・再実装=1点／既出の言い換え=0点 |
| 検証容易性 | 0-2 | コード・データ・プロンプトが公開されているか。既存のAPI/モデルで再現できるか。学習が必要なら1点以下 |
| 主張の強度 | 0-2 | アブレーション・人手評価・ベースライン比較・限界の明示があるか。ベンチ1本の勝ちだけなら1点、デモのみ0点 |
| リスク | 0〜-2 | 法規（景表法・個人情報・著作権）、ブランドセーフティ、被験者同意、再現不可能性。該当あれば減点し**理由を必ず書く** |

満点16点。

## 判定

| 評価 | 点数 | 扱い |
|------|------|------|
| S | 13以上 | 全文を読む。`paper-explainer` に渡して解説を作る。検証タスクを1つ起票する |
| A | 10-12 | 要旨+図表を読む。「使いどころ」を3行で書いてSlackに流す |
| B | 6-9 | 1行要約のみ。週次ダイジェストにまとめる |
| C | 5以下 | 記録のみ。レポート本文には出さない |

S・A が全体の15%を超えたら基準が緩んでいる。減点根拠を見直す。0件の日は0件と報告してよい（無理に埋めない）。

## 2種類の差分化

**(1) バケツ間の差分** — 1本の論文は必ず主バケツ1つに属し、残りは副タグにする。同じ論文が複数バケツに重複掲載されるのを防ぐ。取得スクリプトが予備スコアで主バケツを仮決めするので、内容を読んで違うと判断したら上書きする。

**(2) 既知との差分** — 採点前に必ず `state/known-topics.md` を読む。既知の主張と実質的に同じ論文は、手法が新しくても差分性0-1点にする。ここが甘いと毎週同じ話が上がってきてフィードが死ぬ。

S・A と判定した論文は、トリアージ後に `state/known-topics.md` へ1行追記する（`YYYY-MM / arXiv ID / 主張1文 / バケツ`）。次回の差分判定の基準になるので、これを飛ばすと仕組みが劣化する。

## 出力に必ず含めるもの（S・A評価）

1. **何が新しいか** — 既知との差分として1文で。「〜ができる」ではなく「従来は〜だったが、〜」の形
2. **使いどころ** — 工程 × 指標。例:「クリエイティブ制作の初稿生成、制作工数-30%を狙える」
3. **明日試せる最小検証** — 1つだけ。工数見積（半日／2日／1週間）を付ける
4. **落とし穴** — 前提条件、データ量、コスト、法務論点のうち該当するもの

3が書けない論文は、実質Bである。評価を下げる。

## 判断に迷ったときの原則

- 「弊社の誰が、いつ使うか」が言えない論文はSにしない
- ベンチマークの数字が大きいだけの論文は、測っている対象が実務指標と一致しているか確認する
- 論文が主張していないことを補って良く読んではいけない。書いてある範囲で採点する
- サーベイ論文は原則A上限（実装の差分を生まないため）。ただし新領域の初回サーベイは例外
