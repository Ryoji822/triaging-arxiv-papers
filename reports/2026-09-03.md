# arXiv 論文トリアージレポート
**対象期間：2026年09月01日〜2026年09月03日**

## 今週の要点
- **生成・運用ともに「一発勝負」から「検証可能な中間状態を挟む工程化」への移行が鮮明。** T2Iの空間指示はプロンプト改良（既知の限界：緩和は29.2%止まり）から、検証・修復可能な3Dレイアウト状態を挟むループでOverall 9.37/10（最強ベースライン7.90）に到達（SpatialGuard）。テキスト描画も「文字が正確でも意味が指定領域外に漏れる」現象が測定可能になり（T2LSC-Bench）、検品の共有基準が整いつつある。
- **「人手ラベル」を「VLM教師の推論ごと蒸留」で置き換える流れがエンティティ解決に到達。** 関係定義が変わるたび数週間のアノテーションを回していた業務が、10Kサンプル・日単位の再適応に変わる（MERGED、Amazon・8言語18カ国の実データでPR-AUC 90.96%）。
- **人間側のLLM監督のボトルネックは「知識」ではなく「検索可能性」。** レビュー前に自分で根拠を書かせるだけで誤り検出+10.6pt・偽陽性も低下、検出力は日次で衰えるが自己生成キューが低下を1/3相殺（中国のエンタープライズソフトウェア企業640名・RCT2件）。
- **エージェント評価が「ベンチの点数」から「展開条件の資格判定」へ。** 自律精度72.8% vs 72.5%の2システムが、同じ信頼性76%を達成するには人間レビュー39.2% vs 29.6%を要求する（READY）。本番レコメンダの継続チューニング閉ループ化（CORAL）も2プラットフォームの本番A/Bで有効性を実証。

### [同僚としてのエージェント] Knowing Is Not Enough: Information Retrievability as a Precondition to Effective LLM Oversight
- **arXiv**：[2609.01976](https://arxiv.org/abs/2609.01976) / 2026-09-02 / cs.HC
- **何が新しいか**：従来のLLM出力レビュー失敗の説明は「レビューする能力がない」「腰が重い」の2本で、対策も能力研修と強制だった。本論文は第3の前置条件「レビューに必要な情報がレビューの瞬間に取り出せる状態にあるか（情報の検索可能性）」を提示し、**レビュー前に自分の言葉で根拠を書かせる（生成的符号化）だけで、システム提供の説明を読むより誤り検出率が0.68→0.78（+10.6pt、p<.001）、偽陽性も-3.0pt 低下**することを640名の顧客接点従業員×RCT2件で示した。検出力はLLM使用の常態化とともに日次-2.5ptで衰えるが、自己生成の検索キューが低下率を-1.7pt/日に緩和（約1/3相殺、p=.013）。
- **使いどころ**：AIレポート・提案書・商談メール下書きのQA工程と、AIツール導入時のオンボーディング設計。エラー検出率・偽陽性率（手戻りコスト）・監督の持続性。
- **明日試せる最小検証**（半日設計+1週間運用）：AI下書きをレビューするチーム1つを「そのまま見る」「レビュー前に妥当と思う根拠を1行書いてから見る」の2群に分け、仕込み済みエラー10件入りサンプルで検出率を比較。翌週から毎朝前日の自己根拠を1文見せて再検測。
- **落とし穴**：単一組織（中国・エンタープライズソフトウェア）・メール下書きタスクでの実証。効果の大きさはタスクと対象LLM依存の可能性。介入は軽量だが「根拠を書く」工数（1件あたり数分）がスループット要求の高い現場で持つかは自社で測る必要がある。

### [セマンティックレイヤーとオントロジー運用] MERGED: Multimodal Entity Resolution via Generated Expert Reasoning Distillation
- **arXiv**：[2609.01913](https://arxiv.org/abs/2609.01913) / 2026-09-01 / cs.IR
- **何が新しいか**：商品エンティティ解決（ER）は関係定義が変わるたびに人手アノテーションを数週間回す必要があった（定義変更=新タスクの再構築）。MERGEDは2つの大型VLM教師にラベルと推論を生成させ、**合意ペアでSFT・不和ペアをメタジャッジで好みペアに変えてDPO**に振り分け、人手ラベルなしで7B学生を訓練。8言語18カ国・10万ペアの実ECデータで人手ラベル訓練比+13.79%のPR-AUC 90.96%、32B VLMゼロショット比+6.32%を1/6コスト（$600/100万予測）で達成。利得の内訳はラベル置換+3.5ptに対し推論蒸留+6.1pt・DPO+4.2ptと、**「推論ごと蒸留」が主効**。既存チェックポイントからの再適応は新関係定義に10Kサンプルで89.48%（スクラッチ訓練を上回る）。
- **使いどころ**：ECカタログ運用の商品データ統合・重複排除・関係分類（exact/variant/substitute）。適応リードタイム（週→日）・PR-AUC・予測コスト。
- **明日試せる最小検証**（1週間）：既存の商品突合タスク（CSV数万行）で2つのVLMに合意ラベル+根拠を生成させ、合意率とラベル品質（既知サンプル100件）を測る。合意率が高ければ7B LoRAのSFTまで。合意ペアだけでどれだけ捌けるかが投資判断の最初の門。
- **落とし穴**：学習が必要（SFT+DPO。LoRA規模とはいえGPUと教師APIコストが乗る）。評価データはAmazon内部データで非公開、手法とプロンプトは付録公開。適応実験はexact→variantの1転移のみ、教師2体の最適数は未検証（Limitationsに自記）。关系定义の変更頻度が低い業務では元が取れない。

### [広告クリエイティブ生成] SpatialGuard: Harness-Guided Verifiable Spatial Reasoning for Text-to-Image Generation
- **arXiv**：[2609.01582](https://arxiv.org/abs/2609.01582) / 2026-09-01 / cs.CV
- **何が新しいか**：T2Iの空間指示失敗への対処はプロンプト改良か事後スコアリングで、台帳既知のVLMゲート書き換えでも緩和は25.0%→29.2%止まりだった。SpatialGuardは空間意図を**編集・検証可能な3Dレイアウト状態（物体位置・サイズ・方位・カメラ）に外化**し、「計画→実現→検証→修復」のループで回すエージェントハーネス構造（学習不要・GPT5+FLUX.1 dev）を導入。Gemini 2.5 Pro/Qwen3-VL/Grok 4の3VLMブラインド採点でOverall 9.37（最強ベースラインHunyuanImage-2.1は7.90）、特にDepth +2.18・Support +1.81・Relation +1.42と関係密な場面で大差。アブレーションで4要素の寄与を分離。
- **使いどころ**：商品配置・人物の前後関係・カメラ指定が効くクリエイティブ制作（商品シーン・ストーリーボード）。空間忠実度と再トライ率（制作工数）。
- **明日試せる最小検証**（半日〜2日）：多物体の位置関係プロンプト20件で「FLUX単発生成」vs「LLMに3DレイアウトJSONを出させてから条件生成」を比較し、VLM採点で空間違反数を数える。検証・修復なしでもレイアウト外化だけで利得が出るかが分岐点。
- **落とし穴**：評価がVLMジャッジのみで人手評価がなく、評価プロンプトセットの規模も本文に明記がない（数値の絶対値はジャッジ依存）。推論コストが単発生成より高い（最大4ラウンド）。最終画質は下位生成器に依存。コード公開の記載がないため再現は設計流用になる。

### [広告クリエイティブ生成] T2LSC-Bench: Benchmarking Localized Semantic Control in Text-to-Image Generation
- **arXiv**：[2609.02255](https://arxiv.org/abs/2609.02255) / 2026-09-02 / cs.CV
- **要点**：商品ラベル・サイネージ制作で要求される「指定領域内にテキストを描き、領域外にその意味を漏らさない」性質を初めて測定するベンチ。50被写体×1,200プロンプト×6モデルで、ストレス条件下で意味漏出率（SLR）は1.2%→18.1%に悪化する一方、テキスト描画精度は91.4%→90.9%とほぼ不変＝**文字は正確でも意味が隣接コンテンツに染み出す**。アンチリーク指示のプロンプトでSLRを16.6%→8.4%に半減。420枚の人手検証と一致。
- **使いどころ**：パッケージ・ラベル・バナーの生成検品基準（SLR/cSLRをNG判定に組み込む）。文案とビジュアルの干渉による差し戻し率。

### [エージェント制御] CORAL: An LLM-Native Harness for Production Recommender Systems
- **arXiv**：[2609.02730](https://arxiv.org/abs/2609.02730) / 2026-09-02 / cs.AI
- **要点**：本番レコメンダの継続チューニング（人間アルゴリズムエンジニアがA/Bで回す仕事）を、操作信号を観測→過去の決定と結果の記憶を参照→数値最適化ツールで予算内で再構成する閉ループに置換。2つの大規模ソーシャルプラットフォームの本番A/Bで、同一ハーネスが片方でエンゲージメント向上（サービングコスト不増）、もう片方でコスト削減（エンゲージメント不減）を達成し、反復とともに改善。パラメータ更新なしの文脈内改善。
- **使いどころ**：配信・レコメンド運用の継続最適化を人間エンジニアの工数からエージェントループへ移す検討。エンゲージメント・サービングコスト・実験スループット。ただし評価対象は内部プラットフォームで再現検証は不能、自社小規模閉ループからの検証が必要。

### [エージェント制御] READY or Not: Reliable Enterprise Agent Deployment
- **arXiv**：[2609.02095](https://arxiv.org/abs/2609.02095) / 2026-09-02 / cs.AI
- **要点**：ベンチマーク成績は「仕事をできるか」を測るだけで「許容される信頼性で、監督コストとトレードオフの下で展開できるか」を測らない。READYは各ワークフロー自身の成功定義を保ったまま、信頼性ターゲットを満たす最小コストの監督ポリシーを探索し統計的に資格判定する枠組み。臨床監査16システム・750ケースで、自律精度0.3pt差の2システムが同じ76%信頼性に届けるのに必要な人間レビューは39.2% vs 29.6%と分岐することを示した。
- **使いどころ**：社内エージェント（レポート自動化・配信運用支援）の本番投入判定と監督設計。必要監督率・単位あたり運用コスト。実証は臨床監査1ドメインで、広告運用への転移は自社で検証要。

### [マーケティング調査] Investigating Assistant Bias in LLM User Simulators Using a Role Vector
- **arXiv**：[2609.00608](https://arxiv.org/abs/2609.00608) / 2026-09-01 / cs.CL, cs.HC
- **要点**：LLMユーザーシミュレータが「協調的で課題達成志向になりすぎ、実際のユーザーの不満や離脱を再現しない」問題（assistant bias）を、ユーザー視点とアシスタント視点の活性化の差から「ユーザーロールベクトル」として抽出。ユーザー方向は活性化内で識別可能で、steering は現実性を強めるが、強めすぎると個別ユーザーのプロファイルを上書きしてしまう（プロファイル保持とのトレードオフ）。
- **使いどころ**：シミュレーション調査（silicon sampling）の品質管理。ペルソナ別シミュレーションの歪み診断。既知の simulator collapse（2608.12253）と補完する表現レベルの分析。

### [広告クリエイティブ生成] Blending Concepts: Benchmarking Visual Metaphor Generation in Text-to-Image Models
- **arXiv**：[2609.02502](https://arxiv.org/abs/2609.02502) / 2026-09-02 / cs.CV
- **要点**：広告表現の核心であるビジュアルメタファー（異ドメインの掛け合わせで抽象概念を伝える）の生成能力を初めて系統測定したベンチ。実務の創作物から1,500メタファー（3水準10カテゴリ）、9,594問のMCQ採点+3次元評定。11モデル中最強の専用モデルも構成的構造化とクロスドメイン写像で苦戦し、プロンプトの具体度を上げても埋まらない差距がある。
- **使いどころ**：コンセプトビジュアル（比喩・掛け合わせ表現）の制作でT2Iモデル選定する際の比較軸。案出し段階での「メタファーは人間が描き、AIが着地させる」分担の根拠。
