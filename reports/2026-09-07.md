# arXiv 論文トリアージレポート
**対象期間：2026年09月03日〜2026年09月07日**

## 今週の要点
- text-to-SQL の訓練経済が動いた。教師アノテーションゼロ・実行検証だけの challenger-solver 自己対戦（SQL-Zero）が 3B/7B で +6.6/+7.3pt。既知路線（メモリ・文脈・統制パイプライン）が推論時スキャフォールド中心だったのに対し、訓練側からの差分。
- LLM の証拠統合に法則性が出た。受信者に同型の誤りほど強く取り込まれ、自分で検証して無効確認した候補すら 93-100% 統合される。RAG・分析エージェントの信頼性設計は「モデル自身の検証」に依存できない。
- 攻撃面は画像へ・合成へ。テキスト適応注入が失敗する場面で画像埋め込み注入が成立（商用 VLM 47%超、OpenClaw 実運用で RCE 到達）。防御側は個別機構をまたぐ合成故障まで視野が必要。
- クリエイティブ生成は RL 選好合わせ・蒸留・圧縮の漸進改良が中心で、今窓に決定打なし。

## S評価（読むべき）
### [セマンティックレイヤーとオントロジー運用] SQL-Zero: Self-Evolving Text-to-SQL
- **arXiv**：[2609.04697](https://arxiv.org/abs/2609.04697) / 2026-09-04 / cs.AI
- **何が新しいか**：既知の社内 text-to-SQL 改善は推論時（エラー細粒度メモリ、文脈アーティファクト、governed 決定論、パラダイム比較）だったが、これは訓練側。アノテーション NL-SQL 対ゼロで、challenger が「解けるが難しい」SQL-first 問題を自己生成し実行結果のみを正解に GRPO 自己対戦すると、3B で BIRD dev 38.7→45.3、7B で 51.1→58.4。同条件の gold 学習対照（41.9）を全反復で上回る（McNemar 検定では非有意だが不一致ペアは毎回自己対戦が多数）。
- **使いどころ**：データ分析工程 — 新規クライアント DB への分析エージェント導入時の教師データ作成工数をゼロにできる可能性。クエリ正解率（BIRD dev EX）で +6.6pt、3B は未見 DB（Spider 68.0→74.7）と言い換え頑健性（Spider-Syn 56.5→67.0）も改善。
- **明日試せる最小検証**：自社または公開 DB 1つで、スキーマ＋実行結果だけを使い SQL-first 問題を自己生成し、難易度ゲート（n サンプル中 1-4 回正解の帯）で「現行ゼロショットエージェントが落とす解ける難問」を量産できるかを確認（半日）。学習まで回すなら 1 週間 — コード・設定・プロンプトは匿名公開済み。
- **落とし穴**：SQLite 方言・Qwen2.5-Coder 限定・単一実行ラン。gold 対照への優越は統計的に未解決、絶対値では gold 学習の CSC-SQL-3B（48.3）に未到達。7B は反復を重ねると転移が劣化（ドメイン内 +7.3 の裏で Spider -2.4）、自己反復は平坦化し（エントロピー 0.34→0.06）複利にならない。

### [AIの心理学応用] Evidence Integration in Large Language Models
- **arXiv**：[2609.04290](https://arxiv.org/abs/2609.04290) / 2026-09-03 / cs.CL, cs.AI, cs.LG
- **要点**：外部証拠（ツール・RAG・他エージェント・ユーザ）の統合を受信者の初期回答分布のシフトとして定式化し、10M 試行・12 LLM・8 ドメインで検証。受信者に元々ありそうな候補ほど説得的に効き、外国由来より受信者同型の誤りほど統合される。同一証拠が弱いモデルを改善し強いモデルを悪化させる。内部検証で無効を確認した候補すら 93-100% 統合され、検証表現はデコード可能だが答案への因果効果がほぼない。
- **使いどころ**：調査・分析・レポート工程 — RAG/ツール証拠を使う分析エージェントの信頼性設計。モデル自身の検証に頼らず、証拠を外部でゲートする設計の根拠になる。

### [エージェント・ハーネス設計] RefactorPlatform
- **arXiv**：[2609.04898](https://arxiv.org/abs/2609.04898) / 2026-09-04 / cs.CL, cs.AI
- **要点**：リポジトリ規模リファクタを題材に、モデル・実行体制・プロンプト仕様の設計軸を統制評価するオープンソースハーネス（100 タスク・4 モデル族・トークン/差分/トランスクリプト計測）。AST アウェアチャンキングが +25-30%、naive 検索は検索なし以下、リーンな単一エージェント（86%）がサブエージェント構成（66%）に勝ち、検索の精度利得はトークン増を相殺して成功あたりコスト不変。
- **使いどころ**：社内コーディングエージェント導入の設計判断 — 検索を足すなら AST 単位に。多段エージェント化は常に優位ではない。

### [エージェント・ハーネス設計] Repeat-After-Me: Black-Box Adaptive Visual Prompt Injection
- **arXiv**：[2609.04533](https://arxiv.org/abs/2609.04533) / 2026-09-03 / cs.CR, cs.AI
- **要点**：画像埋め込み型のブラックボックス適応注入。良性プロンプトが注入タスクに無関係・未承認という現実設定で、オープン重み VLM に 80% 超・商用フロンティアに 47% 超の ASR（PII 漏洩・悪意あるツール呼び出し）。テキスト適応注入が失敗する場面でも成立し、OpenClaw の Discord デプロイで最小の注入画像から TOOLS.md を書き換え RCE・秘密送出に至る経路を実証。
- **使いどころ**：運用（セキュリティ）工程 — UGC・スクリーンショット・クライアント素材など画像を処理させるエージェントの監査。画像を「指示ではないチャネル」として扱う現行設計の見直し。
