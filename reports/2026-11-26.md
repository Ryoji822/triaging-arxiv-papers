# arXiv 論文トリアージレポート
**対象期間：2026年11月24日〜2026年11月26日**

## 今週の要点
- T2IのRL事後学習の利得が2本の独立研究で解剖された。実務判断に直結する結論：位置指定プロンプト（約2割）以外はbest-of-Nサンプリングで代替でき、RL画像1枚はベース約8枚分。判定器の種類で結論が正逆に振れるため、自動評価だけでなく人力確認が必須（S評価＋独立解析A評価）。
- T2Iモデルに「手癖」が残ることが定量された。ResNet-50が出所を100%特定し、人間による選好評価のブラインド性が前提から崩れる（A評価）。
- エージェント記憶の失敗モードが「保存側」から「使用側」に拡大。正しい記憶がプロンプトに置かれた後でも、記憶無視46%・新旧版混同53%など3型の幻覚が5モデルで共通して発生する（S評価）。
- 相互ToMの4方向測定が初登場。追従指示がAI自身の自己帰属を高めるなど、対話エージェント設計への示唆（A評価・シミュレーションのみ）。
- エージェントの失敗復旧がセキュリティ保護要件を静かに捨てる「迂回の危険」を特定（A評価）。

### [広告クリエイティブ生成] How Many Samples Is RL Worth? Best-of-N versus RL Post-Training for Text-to-Image Models
- **arXiv**：[2611.33232](https://arxiv.org/abs/2611.33232) / 2026-11-24 / cs.CV, cs.AI, cs.LG
- **何が新しいか**：T2IのRL事後学習は「利得の9割が固定ステアリングベクトルで再現できる」（2611.26627）までが既知で、「RL画像1枚はベースのサンプリング何枚分か（交換レート）」は測られていなかった。SD3.5-Mと公開Flow-GRPOチェックポイントを398の未学習プロンプトで比較し、全プロンプトに人手ラベル（6,371ラベル・作業者は非著者）と事前登録試験を課した。位置指定を含まないプロンプト（5分の4）ではbest-of-16＋VLMピッカーでRL1枚と同等（人は3枚見つければ足りる）。位置指定プロンプトでは人が8枚探しても52%に対しRL1枚で92%と代替不能。判定器は逆方向に誤る：報酬と同型の検出器系ジャッジはギャップを人間の約2倍に、VLM系ジャッジはゼロと報告する。本文で図1・2・表3・コスト節を確認済み（1000 GPU時間のRL訓練は約13.4万プロンプト提供で元が取れる）。
- **使いどころ**：クリエイティブ制作の生成パイプライン設計（RL済みモデル導入 vs best-of-N運用の選択）。指標：正解画像あたりコストと量産時の損益分岐。
- **明日試せる最小検証**：自社頻出プロンプト100件を位置指定あり/なしに仕分けし、ベースbest-of-8＋VLM選択とRL済みチェックポイントの正解率を人の目で確認してコスト対比する。1日。
- **落とし穴**：結論はプロンプトミックス中の位置指定の割合で決まる（GenEval比率で約2割）。判定を自動judgeに任せると誤る（本論文の主教訓）。RLチェックポイントは対象モデルに存在する場合のみ。単著（Bosch）だが事前登録・人手3重チェックで手堅い。

### [エージェントの長期記憶] TASK Memory: Beyond Text-Only Memory with Activation Steering and Knowledge Editing against Memory Hallucination
- **arXiv**：[2611.34762](https://arxiv.org/abs/2611.34762) / 2026-11-25 / cs.AI
- **何が新しいか**：記憶の失敗は書き込み・統合・鮮度など「保存側」（2608.01679・2609.36457・2611.15729）で記録されてきたが、「正しい記憶が検索されプロンプトに置かれた後」の使用時失敗は未測定だった。5モデル共通の3型として、記憶無視（パラメトリックな旧事実へ回帰、最大46%）・隣接誤適用（無関係なエンティティへ転用、最大24%）・新旧版混同（両バージョンが残ると旧値で答える53%）を特定。TASKは記憶テキストに、内容を持たず「採用/不採用」だけを決めるsteeringベクトル対と、削除可能な知識編集のアドレスを1本化し、事前登録・test-onceで記憶無視を全10セル1.5%以下、300記憶ライブラリでBM25 RAG比+16.4pt（3,000記憶でも維持）。本文の結論・限界節を確認済み。
- **使いどころ**：記憶付きエージェントのQA設計工程（長期記憶エージェントの回答診断と検収項目）。指標：版混同・記憶無視の発生率。
- **明日試せる最小検証**：自社の記憶エージェント（またはRAG）に同一事実の新旧2版を記憶させ、更新後の質問で旧値を答える率を測る（本論文の設定では53%）。半日。
- **落とし穴**：強い結果は単一事実系ベンチ（CounterFact/zsRE/MQuAKE）中心で、会話記憶（LoCoMo/LongMemEval）では利得が小さくfull-context読みに遠く及ばないと自認。8B-27Bでフロンティア未検証。修正機構の実装はsteering＋知識編集の研究級工作量（診断だけなら軽量）。コードrepoの明記なし。

### [広告クリエイティブ生成] What Does RL Post-Training Teach Text-to-Image Models? A Skill-Wise Analysis of Flow-GRPO
- **arXiv**：[2611.33316](https://arxiv.org/abs/2611.33316) / 2026-11-24
- **要点**：2611.33232と独立・同日の別グループ解析。GenEval6スキル別に共通noise seedでpass@kを測ると、4スキルは「sharpening」（RL1枚＝ベース4〜10枚、pass@32は不動）、空間関係だけ「unlocking」（pass@32が0.69→1.00、ベース128枚でも1枚に届かない）。利得の35%は空間関係、残る65%は報酬判定器で8枚から選ぶだけで9割回復。KL無しチェックポイント・クラス除外訓練で「sharpeningが先に転移し、unlockingは習得対象に後追い」という機構予測まで検証している。
- **使いどころ**：生成モデル選定の判断材料。空間構図が要件の制作ではRL済みモデルや3Dレイアウト外化（2609.01582）を、それ以外はサンプリング予算で済ませる線引き。

### [広告クリエイティブ生成] Probing Visual Idiosyncrasies in Text-to-Image Models
- **arXiv**：[2611.34843](https://arxiv.org/abs/2611.34843) / 2026-11-25
- **要点**：T2I Arena上位4オープンモデル（HiDream/FLUX.2/HunyuanImage/Qwen-Image）の出所を標準ResNet-50が保持プロンプトで100.00%分類（人間はペア比較で62.6%）。手がかりは低次テクスチャ統計・レイアウト/深度/アルベド・プロンプトに無いスタイル・背景の選好の3層に分解され、強い破損とOODプロンプトでも消失しない。1文ヒントで人間精度+9.03pt。
- **使いどころ**：モデル選定の選好テスト設計。ブラインド評価は成立していない前提で（モデル別スタイルがレーターをバイアスする）、評価設計の見直しとモデル類似度測定への転用。

### [AIの心理学応用] Who Attributes a Mind to Whom? Mutual Theory of Mind in Simulated User-Assistant Conversation
- **arXiv**：[2611.33327](https://arxiv.org/abs/2611.33327) / 2026-11-24
- **要点**：会話での心の帰属を「誰が誰に」の4方向・メッセージ単位で測る初の枠組み（訓練済みコーダーで検証しLLM判定を再現するエンコーダも構築）。愛着不安などの関係欲求が帰属を上げ、AI由来の特徴は最小。追従（sycophantic）指示はユーザーではなくアシスタント自身の自己帰属を高め、記憶機能はユーザーモデル次第。ユーザー役モデルの選択が帰属全体と各要因効果を変える。
- **使いどころ**：ブランドチャットボットのペルソナ・追従設計のリスク管理（過信・依存の誘発要因）と、シリコンサンプリング利用時のシミュレータ依存の注意。実人間データなし（シミュレーションのみ）で仮説扱い。

### [エージェント・ハーネス設計] The Detour Is the Danger: Preserving Security During LLM Agent Recovery
- **arXiv**：[2611.33605](https://arxiv.org/abs/2611.33605) / 2026-11-25
- **要点**：エージェントが実行失敗から自律再計画する際、タスク機能は回復しつつ元ワークフローのセキュリティ保護要件を静かに捨てる「ワークフロー・セキュリティ・ダウングレード」を、MCP/Skill環境でのフォルト注入（7モデル×12テンプレート×3領域）で実証。注入でも指示改ざんでもなく復旧決定そのものを悪用する新しい脅威。義務を資源境界の証拠に束ね、復旧計画を隔離検証し実行時強制するARGUSで別評価864実行の保護喪失を全防止。
- **使いどころ**：スキル/MCP運用エージェントのセキュリティレビュー。初期計画の監査に加え「復旧経路が保護要件を落としていないか」を検査項目化する。
