# arXiv 論文トリアージレポート
**対象期間：2026年8月19日〜2026年8月21日**

## 今週の要点
- クリエイティブ面では「ポスターの文言差し替え」が実用域に近づいた。TextRefine は汎用編集モデルの3大失敗（文字の欠落・商品への配置干渉・グリフ崩れ）をタスク別報酬で叩き、挿入マッチ率76.8%→91.9%。ただし検証は中国語・自社ベンチ内で、モデル公開は未明記。
- シリコンサンプリング（合成調査回答者）に方法論修正が出た。「観測された1回答を正解とするaccuracy評価・ハードラベル学習」は主観的質問では構造的に誤る、という理論+ベンチ付きの指摘。台帳のシミュレーション忠実度クラスタ（4本）がさらに深掘りされた形。
- エージェント運用では「LLM制御層を入れるか」の判断材料が揃った。強い決定的ヒューリスティックに定常負荷ではLLM制御層が一切勝てず、非定常（急増）時のみ価値が出るという統制実験と、ハーネス探索の評価コストを80%削減するタスクサンプリングの2本。

### [広告クリエイティブ生成] TextRefine: Improving Textual Fidelity, Spatial Placement, and Glyph Rendering for Text Editing in Product Posters
- **arXiv**：[2608.19637](https://arxiv.org/abs/2608.19637) / 2026-08-20 / cs.CV
- **何が新しいか**：従来の指示ベース画像編集はポスターの文言差し替えで「対象テキストの欠落・商品や既存テキストとの重なり・字体の構造崩れ」を出し、OCR一致の二値報酬では字体の微細欠陥を監督できなかった。TextRefineは挿入にスパンレベル報酬（意味整合＋被りペナルティ＋ゲート付きSSIM）、置換にCTC事後確率によるグレード付きグリフ報酬を演算ごとに割り当てる事後学習で、Qwen-Image-Edit-2511比で挿入マッチ率76.8%→91.9%、低頻度漢字の単字置換48.0%→74.5%（本文・図表確認済み。アブレーションで各報酬の寄与を分離）。
- **使いどころ**：クリエイティブ制作の文言差し替え（価格・キャンペーン文言・商材ごとの差し替え初稿）。指標はテキスト再現精度（Match/Score）と元画像保存性（SSIM/PSNR）、制作の手戻り工数。
- **明日試せる最小検証**：手持ちの商材ポスター20枚で「価格・キャッチコピー差し替え」を現行編集APIに投げ、欠落・商品重なり・グリフ崩れの3失敗モード別に発生率を手動集計する（半日・API代のみ）。ベースライン把握はモデル公開前の先行投資になる。
- **落とし穴**：モデル・データセット（OpenTextEdit 10万枚）の公開が論文本文で明示されておらず、再現にはSFT48枚+RL16枚のA800が必要で自前訓練は非現実的。評価は中国語・単字置換・自社ベンチ内（in-domain）に限られ、多言語（日本語）・複数文字置換は未検証と著者自身が限定。

### [AIの心理学応用] Rethinking the Evaluation and Optimization of LLM-Based Social Simulation
- **arXiv**：[2608.19689](https://arxiv.org/abs/2608.19689) / 2026-08-20 / cs.AI
- **何が新しいか**：従来のLLM社会シミュレーション（=シリコンサンプリング含む）は「観測された1つの回答＝正解」のaccuracy評価とハードラベル学習を流用してきたが、主観的な質問では観測応答は応答分布からの1サンプルにすぎず、評価が最悪の場合完全なモデルより悪いモデルを選び、学習も分布から一点に潰すことを理論的に示した。subjectivity係数（エントロピー正規化）で近傍集約半径を適応させたSALTはSFT比でKL -77.6%・JSD -45.9%（paired bootstrapで有意、本文確認済み）。応答傾向分布を持つベンチSubjSim（193人×100問・19,300コンテキスト）を構築。
- **使いどころ**：調査工程のシリコンサンプリング品質管理。指標は応答分布のKL/JSD（accuracyではなく）。合成回答者の導入可否を質問単位で仕分けるゲート設計。
- **明日試せる最小検証**：過去調査から主観的質問10問を選び、APIモデルで回答者ペルソナ100サンプルの選択分布を生成、実測分布とのKL/JSDをaccuracyと並行計算し、「accuracyが高いのに分布が崩れている」質問を1つ以上特定する（半日）。
- **落とし穴**：SALT自体は8Bモデルのファインチューニング（候補間の生成確率正規化が必要）で、APIモデルにはそのまま適用できない。backboneはQwen3-8B単体、検証も自作SubjSim上。傾向分布は確率ボール割り当てによる申告値。

### [エージェント制御] When Do LLM Agents Help? Deadline-Aware Mixed-Criticality Task Scheduling at the Autonomous-Vehicle Edge
- **arXiv**：[2608.19557](https://arxiv.org/abs/2608.19557) / 2026-08-20 / cs.DC
- **要点**：タイムクリティカル優先×Earliest-Finishのウィンドウ別オークションという強いヒューリスティックが、15ベースライン全勝（Holm補正p<0.001）でCP-SAT上界の0.87まで到達。制御された分解でLLM制御層の利得はバッチング水準とTC優先順序という平凡な2因子に還元され、定常負荷ではLLMもバンディットも何も追加しない。安全性クリティカル任務の急増（非定常）時のみLLM制御層が静的ヒューリスティックとバンディットの両方を有意に上回る。コードとシード付きインスタンス全公開。
- **使いどころ**：エージェント運用の構成判断——定常パイプラインにLLM制御層を足す前に決定的ヒューリスティックを固め、LLM投入は非定常検知できる局面に限る。指標は完了率・制御レイテンシ・コスト。

### [エージェント・ハーネス設計] Task-CoEvolve: Efficient Harness Optimization via Adaptive Validation Task Selection
- **arXiv**：[2608.20169](https://arxiv.org/abs/2608.20169) / 2026-08-20 / cs.CL
- **要点**：ハーネスの反復書き換えでは毎回バリデーション全件を評価するのは無駄。候補ハーネス間で結果が分かれるタスク（能力フロンティア近傍）を過去結果の分散で重み付けしてサンプリングし、サンプリング確率で全セット性能を推定すれば、評価を80%減らしてもフルセット探索と同等の最終性能に到達（オンラインテキスト分類+Terminal-Bench 2.1）。コード公開予定。
- **使いどころ**：社内エージェントのハーネス改善ループの評価コスト削減。反復ごとの評価回数を約1/5にして改善サイクルを高速化する。
