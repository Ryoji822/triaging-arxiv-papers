## 今週の要点
- エージェント記憶に反説が出た：enterprise設定では保持・鮮度は0.93-0.98で飽和しており素のRAGと記憶システムに差がなく、本当のボトルネックは「解決（どの主体・どの時点か、答えるか棄権か）」（DISCERN）。記憶システムの投資先を検索からエンティティ・時点解決に変える根拠になる。
- 統制・安全系は「検証可能性」が主戦場になった。SLMが自ら書くセキュリティ成果物は15モデル中11-14で攻撃を通す（CapLite）、ゲートウェイが実際にどこを検査できているかのカバレッジ測定（guardscope）、安全拒否自体が攻撃面になる（over-abstention）。
- 実験設計では「マーケットプレイス実験は短辺（少数側）をランダム化せよ」がバイアス・分散の両面で優位するという理論的処方箋（One-Sided Randomization）。
- クリエイティブ生成は広告指標への直結が進む：記憶に残る動画生成（MemCrafter、ただし予測指標のみ）、「描くな」が描かれる事故の計測と検出器（OverReal）。

### [エージェントの長期記憶] DISCERN: Preserve at Write, Resolve at Read for Persistent LLM-Agent Memory
- **arXiv**：[2611.15729](https://arxiv.org/abs/2611.15729) / 2026-11-11 / cs.AI
- **何が新しいか**：従来の記憶システム研究は検索（recall）の改善を競ってきたが、enterprise記憶ではretention・currencyがどのまともなシステムでも0.93-0.98で飽和しており素のRAGと差がないことを示し、未解決は「resolution」（クエリがどのエンティティ・どの時点を指すか、証拠不十分なら棄権するか）だと特定した。書き込み時は混同しやすいエンティティを決してマージしないbi-temporalな来歴グラフを厳密に蓄積し、読み出し時にLLMなしのツール面でグラフを巡回して4値のゲート付き終端アクションに確定させる。
- **使いどころ**：社内・顧客向けエージェントの記憶設計・製品選定。回答正解率（マクロ0.861 vs 最強ベースライン0.806）と棄権キャリブレーション（F1 0.924 vs ≤0.802）、エンティティ解決0.800（全ベースライン≤0.40）。チューニングなしでLoCoMoでも首位（0.663 vs 0.638）。
- **明日試せる最小検証**：自社の対話ログから「同姓の別主体」「更新済みの旧情報」を含む20問を作り、現行の記憶システムと素のRAGで正解率・棄権適否を比較（1日）。差がresolutionに集中するなら投資先の転換根拠になる。
- **落とし穴**：主ベンチENT-310は合成、採点は4-judge LLM評議会。書き込み時の来歴グラフ蓄積・巡回コストのスケール検証とコード公開の明記は本文確認要。

### [データ分析] One-Sided Randomization in Two-Sided Platform Experiments: Which Side Should be Randomized?
- **arXiv**：[2611.16406](https://arxiv.org/abs/2611.16406) / 2026-11-12 / stat.ME
- **要点**：マーケットプレイス実験で顧客側か出品側のどちらをランダム化するかは「バイアスvs分散のトレードオフ」とされてきたが、FCFSマッチングでは短辺（少数側）ランダム化が両方の次元で優位する（一次の干渉バイアスを消し、分散レートも劣らない。マッチ数が短辺側の人口で制約されるため長辺の標本数優位が幻想）。異質な選好・効果を許容し、ロジット選択モデルで成立。
- **使いどころ**：EC・マーケットプレイスクライアントの実験設計（調査工程）× 推定バイアス・必要サンプルサイズ。

### [エージェント・ハーネス設計] CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts
- **arXiv**：[2611.17115](https://arxiv.org/abs/2611.17115) / 2026-11-12 / cs.AI, cs.CR
- **要点**：CaMeL/Progent/IPIGuard/DRIFT系の「モデル自身にセキュリティ成果物を書かせる」防御は、SLM（1.7B-12B、15モデル中13）では書かれたポリシー・グラフ・制約が攻撃を通し（Progentで14モデル、CaMeLのプログラムは最大68%のエピソードで実行失敗）、信頼できない。ツールスキーマからポリシーを導出し、ツール結果を読む前に書き込みコールを確定し、影響先を決める全引数がユーザ依頼に明示されている場合のみ書き込みを許可するCapLiteは13,935攻撃エピソードで侵入ゼロ、utility 29.0%（CaMeL 27.2%）、トークンはCaMeLの18%。
- **使いどころ**：小型モデルエージェントの注入防御設計 × 攻撃成功率・utility・トークンコスト。

### [エージェント・ハーネス設計] guardscope: Measuring Which Actions Runtime Controls Check in LLM Agent Systems
- **arXiv**：[2611.15223](https://arxiv.org/abs/2611.15223) / 2026-11-11 / cs.AI
- **要点**：エージェントゲートウェイ等の実行時統制は「置いた地点を横切る行動」しか検査できず、エージェントはツールコール経路以外でも行動する。この網羅率を静的段階（15行動パスの予測）と empiric 段階（8トポロジー設計で実行し、統制の判断記録をカーネルレベルのグランドトゥルースと突き合わせチェック/バイパス/防止に分類）で測定可能にした。Microsoftのagent governance toolkitとagentgatewayで実測。コード公開。
- **使いどころ**：ゲートウェイ・統制製品の導入査定と監査 × 制御網羅率（バイパス率）。

### [広告クリエイティブ生成] When Chekhov's Gun Fires Anyway: Over-Realization in Text-to-Image Models
- **arXiv**：[2611.16630](https://arxiv.org/abs/2611.16630) / 2026-11-12 / cs.CV
- **要点**：プロンプトに言及した対象が指示していない形で描かれる「over-realization」を、否定・信念/想像・比喩・隠蔽の4状況で定義・計測した。8システムすべてが発生し、CLIPScore等の整合指標はこの失敗を罰するどころか報酬する。プロンプト拡張は部分的にしか効かず、拡散バックボーンは抑止語句にほぼ注意を払わない。人手ラベル2,841画像で検証済み検出器（OverReal-Det）付き。
- **使いどころ**：クリエイティブ自動検品（ネガ指示「ロゴを入れない」等の違反）× 指示違反検出率・修正工数。否定の未抑制自体は2611.09304と重複するが、検出器と4状況への拡張が差分。

### [広告クリエイティブ生成] From Seeing to Remembering: Brain-Informed Agentic Text-to-Video Generation for Enhancing Memorability
- **arXiv**：[2611.15107](https://arxiv.org/abs/2611.15107) / 2026-11-11 / cs.CV
- **要点**：動画の「記憶に残りやすさ」を最適化対象にした初めての生成研究。皮質領域ベースの神経応答推定から記憶性予測信号を構築し、感度分析に基づくフィードバックでプロンプトを反復改良するエージェントが、意味整合と知覚品質を保ちながら予測記憶性を一貫して向上させた。
- **使いどころ**：動画クリエイティブ制作の初稿最適化 × 記憶定着（ブランドリフトの代理）。ただし評価は予測指標のみで人間の記憶検証なし・コード公開の記載なし。採用前に自社動画での人間想起テストによる相関確認が必須。

### [エージェント・ハーネス設計] When Safety Becomes an Attack Surface: Manipulating Abstention in Tool-Using AI Agents
- **arXiv**：[2611.14864](https://arxiv.org/abs/2611.14864) / 2026-11-11 / cs.CR
- **要点**：低信頼コンテンツに捏造のリスク警告を埋め込むだけでエージェントの正当なタスク完遂を妨害できる（availability攻撃）。注意喚起系プロンプトは攻撃を増幅し（Geminiで過剰忌避9.8%→86.3%）、クリーンタスクは不変のまま。警告を権威ある記録と照合するVerify-Before-Abstainは完遂率を改善するが、偽造・機密保持との限界も特定。
- **使いどころ**：消費者向けエージェント・チャットボットの安全設計 × タスク完遂率（ブランドガード設定が外部から武器化されるリスクの検査項目化）。
