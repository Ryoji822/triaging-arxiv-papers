# arXiv 論文トリアージレポート
**対象期間：2026年08月27日〜2026年08月31日**

## 今週の要点
- **「クリエイティブを実行可能コードとして生成する」波が一気に具体化した。** 拡散モデルのラスタル画像が持つ文言崩れ・商品の形状変形・編集不能という実務障害を、HTML/CSS合成＋レンダー後のルール検証（CommerceVibe）や参照プロファイル適応（LandingAgent）で回避する方向に複数の論文が揃った。
- **text-to-SQL の報告が「精度の単一数字」から「モジュール単位の費用対効果」に移った。** 実行フィードバック修復だけが普遍的に効くこと、固定予算はフロンティアモデルより中位モデル＋丁寧なパイプラインに使う方が得ることが、17構成×9バックボーンの統制実験で示された。
- **エージェント防御で「事前に計画・ポリシーを固定する」アプローチの限界が定量化され**（既存防御はクリーンタスク完遂率が1〜2割に崩壊）、値の起源トレースによる決定的強制（ROPE）がセキュリティと有用性の両立解として出た。ただし台帳に既知が集中する領域であり、差分は機構レベルに限定して評価した。
- 備考：長文コンテキストで安全ガードレールが機能しない（LongGuard/LongPIBench）、ペルソナエージェントの焦点群は人間の多様性の一部しか復元しない（FocusGen）は把握 レベル。

### [広告クリエイティブ生成] CommerceVibe: Learning to Design E-Commerce Creatives as Executable Visual Code via Dual-Feedback Reinforcement Learning
- **arXiv**：[2608.27893](https://arxiv.org/abs/2608.27893) / 2026-08-28 / cs.CV
- **何が新しいか**：従来の拡散モデルによるECクリエイティブ生成は、ラスタル画像であるがゆえの文言崩れ・商品詳細の不一致・編集不能を残していた。CommerceVibeは生成を実行可能なHTML/CSSの条件付きプログラム合成に立て直し（商品画像は参照・文言はネイティブ要素）、レンダー後のDOMを「文言可読性・商品視認性・レイアウト妥当性」のルールで検査する報酬とVLM好み評価の二重フィードバックでGRPO学習する。9Bモデルで総合94.0/100（SFTのみ87.3）、**5名の電子商取引デザイナーによる盲検評価で90.0（GPT-5.5は78.9、ICC 0.811）**。マルチ商品ケースでは単一フィードバック比+4.8ptと相補性も確認。
- **使いどころ**：運用型広告のECクリエイティブ大量制作（商品カード・バナー）。制作工数と、文言崩れ・商品変形による差し戻し率。出力が編集可能なコードなので文言差し替え・商品入れ替えが再生成不要。
- **明日試せる最小検証**（半日）：任意のLLMに商品画像+要件からHTML/CSSを単発生成させ、ヘッドレスブラウザでレンダー→DOM検査で「テキスト溢れ・要素重なり・商品画像の欠落」を数える検査パイプラインを1ケースで組む。学習なしでも検査器の設計はそのまま使える。
- **落とし穴**：28,568例でのSFT＋8×H20でのRLが必要で、コード・モデルの公開は本論文に明記がない（再現は「検査器設計の流用」が現実的）。自動評価はRL報酬と同じルールでreward-alignedだが盲検専門家評価が独立裏付け。文言の忠実性（copy faithfulness）はGPT-5.5が依然上位で、景表法が絡む文言は別レイヤーでの検査が必要。ベンチは自社構築で中国EC市場寄り。

### [エージェント・ハーネス設計] ROPE: Routed Origin Policy Enforcement against Indirect Prompt Injection
- **arXiv**：[2608.27496](https://arxiv.org/abs/2608.27496) / 2026-08-27 / cs.CR
- **何が新しいか**：従来のシステムレベル防御（計画追従・許可ポリシー・固定信頼境界）は、委任が多いタスクで事前に固定した制約が役に立たず、AgentDynでは既存防御がクリーンタスク完遂率6.7〜18.3%（無防御46.7%）まで崩れるか、攻撃を通すかの二択だった。ROPEは「状態変更ツールの敏感パラメータに達する値は、ユーザー・ユーザーが明示指定した送信元・ユーザー自身の記録のいずれかに偽造不能にトレースできる場合のみ許可する」決定的な起源検査に切り替え、LLMルータは信頼済みのユーザーリクエストのみ読む。**攻撃成功率1.6〜2.6%を維持しつつクリーン有用性の82〜100%を保持**し、適応攻撃はほぼ無効、従来防御を破る長期段階攻撃は0成功。起源健全性と言い換え不変性の2つの証明付き。ルータは20Bオープン重みまで下げられる。
- **使いどころ**：社内エージェントの本番投入前セキュリティ設計。侵害成功率とクリーンタスク完遂率を同時に扱うミドルウェアの参照実装。
- **明日試せる最小検証**（2日）：公開リポジトリ（コード+ログあり）を自社ツールセット（例：Slack投稿・CRM更新）に接続し、状態変更ツールの敏感パラメータ表を20項目作成。クリーンタスク20件での有用性と、注入テスト5件での阻止率を測る。
- **落とし穴**：保証は「値の起源」であって「ユーザーの意図」までではない。正当な値が攻撃者書き込み可能な経路にしか存在しないタスクは安全側に落ちて失敗する（fail-safe）。前提A1〜A3（起源メタデータの真正性・状態変更ツール列挙の完全性）が実配備で成立要。評価はAgentDyn/AgentDojo中心で、同方式は3件の注入タスク採点を環境効果ベースで再採点している（付録に明記、透明性は高い）。

### [セマンティックレイヤーとオントロジー運用] Are These Modules Worth Their Cost? A Paradigm-Level Accuracy-Cost Analysis of In-context Learning Text-to-SQL
- **arXiv**：[2608.28432](https://arxiv.org/abs/2608.28432) / 2026-08-28 / cs.CL, cs.AI, cs.DB（WSDM 2027）
- **何が新しいか**：text-to-SQLの改良はend-to-end精度の単一数字で報告され、どのモジュールが利得を持つかは不明だった。17パラダイム構成×4バックボーン（＋推論2種＋転移検証5種）の統制実験で、**実行フィードバック修復（実行エラー/空結果のときだけ書き直す）だけが全バックボーンで+1.8〜+4.9ptを一貫した低コスト（CPP<$0.30/pt）で達成**し、他はモデル依存（スキーマリンキングは弱いモデルの補綴で強モデルでは価値が縮む、CoTは非推論モデル限定で推論モデルでは逆効果、候補選択は候補プールの再現率上限で飽和）と判別した。固定予算は「フロンティアモデル+簡素パイプライン」より「中位モデル+念入りパイプライン」に使う方が精度が高い。段階的ガイドラインは5追加バックボーンに探索なしで転移。
- **使いどころ**：社内分析エージェント（text-to-SQL）の構成決定と予算配分。実行精度（EX）とAPIコスト（CPP）。
- **明日試せる最小検証**（半日）：現行パイプラインにR1（実行エラー/空結果時のみの書き直し）を足してEXとコストをBefore/Afterで測る。次に「強モデル直叩き」を「中位モデル+R1+スキーマリンキング」に同じ予算で置き換えて精度を比較する。
- **落とし穴**：コード公開の記載がなく17構成の再実装は重い。BIRD/Spider中心で、数百テーブルの社内スキーマではリンキングの限界点が変わる可能性。McNemar検証・信頼区間付きで統計は丁寧。
