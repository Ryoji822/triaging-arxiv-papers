# arXiv 論文トリアージレポート
**対象期間：2026年10月29日〜2026年11月2日**

## 今週の要点
- 分析スタックの論点が「生成の精度」から「保守の正しさ」に移った。実行は成功のままビジネス定義変更（返金帰属・税率・対象母集団・為替日）で壊れる固定クエリの再検証を定式化した論文（2610.41090）と、エラーメッセージ任せだったSQL修復を静的診断＋適用前検証に組み替えた論文（2610.41472）が同日出一。「正しく実行されるが意味が誤る」クエリの管理が次のボトルネック
- RAGは精度の議論が一段落しつつある。有能な検索ハーネス＋BM25で精度はほぼ出て、構造化（ナビゲーションツリー等）は精度でなくクエリトークン削減（最大91%）の「供給層」だという測定（2610.41172）。GraphRAG投資の判断軸が精度からコスト・ガバナンスに変わる
- エージェント権限は「強制」の前に「見える化」が効く。ツール説明に権限クラスを書くだけで越権ツール選択が最大半減（2610.40975）、承認判断もテキストでなくサンドボックス事前実行の帰結を見る構成（2610.40753）
- 音声LLMの感情認識は「言っていること」と「言い方」の不一致で壊れる。ラベルフリーの不一致スコアでエラー区間を予測可能（2610.40883）——音声データの感情分析を入れる前の品質ゲートになる

### [セマンティックレイヤーとオントロジー運用] Verifying Text-to-SQL Queries under Changing Business Semantics
- **arXiv**：[2610.41090](https://arxiv.org/abs/2610.41090) / 2026-10-30 / cs.AI
- **何が新しいか**：従来のtext-to-SQL検証は「現在のスキーマで正しく実行されるか」の一点で、意味的誤り対策（2608.16663等）もデプロイ時点の生成を前提だった。本論文は「ビジネス定義（返金帰属・税務処理・対象母集団・為替適用日）が変わった後で、既存の固定クエリがまだ正しいか」という再検証問題を初めて定式化し、要求改訂とナレッジカットオフを法的反例データと金額厳密比較に束ねた実行可能な検証プロファイルを提示した
- **使いどころ**：社内ダッシュボード・定型レポートクエリの保守工程。定義変更のたびに起こる静かな誤集計の検出——義務ガイド付き検査は汎用順序比+6.9pt（95%CI [2.1,13.6]、事前登録・p=0.0156）。144の非適合セル中63は現スナップショットでは一致する＝見た目では壊れていない
- **明日試せる最小検証**：最も参照される定型クエリ5本について「返金の定義を変えた」等の改訂シナリオを3つ手で作り、改訂前後で出力が変わるか・変わらない場合どちらが正しいかを反例データ（境界日付・極端な少額）で確認する（半日）
- **落とし穴**：評価は著者自作の32改訂ファミリとローカルモデルの範囲（論文自身が明示的に限定）。コード公開の記載がなく社内適用は自作実装になる。「一致」は記録済みスイート内に限る＝検査通過が正しさの証明にならない

### [セマンティックレイヤーとオントロジー運用] Context as Infrastructure: Knowledge Compilation for Retrieval in Agentic Systems with Harnesses
- **arXiv**：[2610.41172](https://arxiv.org/abs/2610.41172) / 2026-10-30 / cs.IR, cs.AI, cs.CL
- **何が新しいか**：構造化RAG（グラフ・階層・オントロジー）は精度を上げるものとして語られてきたが、有能な検索ハーネス（BM25/grep＋MiniMax M3でmulti-hop FRAMES 91%）の下では構造化アーティファクトは精度に寄与せず（PageIndex型目次はスケールで劣化）、主張-証拠葉を持つナビゲーションツリーは証拠が足りる問いでクエリトークン91%減（平均38%、ブレークイーブン十分率2%に対し実測43%）の「供給層」であると測定した
- **使いどころ**：社内ナレッジRAGの運用コスト削減——平均38%のトークン減、意思決定ゲートでレイテンシ140s→30s。2608.16096（GraphRAG索引コスト11倍差）以降の「構造化に金を払う理由」を精度からコスト・ガバナンス側に再定義する根拠
- **明日試せる最小検証**：RAGFlow（Apache-2.0で公開済み）に社内FAQ・手順書を取り込み、ナビゲーションツリー構築あり/なしで10問の回答トークン・レイテンシ・正答を比較（1週間）
- **落とし穴**：精度数値（BrowseComp-Plus 85%等）は自社環境での自己測定・非標準ベンチ。トークン削減は検索ラウンド増と引き換いの面があり（substitutionのコストを論文自身が明記）、ゲート設計次第で削減幅が変わる。RAGFlow製品の説明を兼ねた論文で競合構成との比較は限定的

### [セマンティックレイヤーとオントロジー運用] Post-SQLFix: Property-Guided Repair of LLM-Generated SQL with Runtime Verification
- **arXiv**：[2610.41472](https://arxiv.org/abs/2610.41472) / 2026-10-30 / cs.SE
- **何が新しいか**：SQL修復は実行フィードバック（EF）のエラーメッセージをLLMに渡す形一辺倒で、提案と判定を同じ未検証モデルに任せる「Arbitration Paradox」を抱えていた（2608.28432の知見はEF修復が唯一普遍的に効くというもの）。本論文は方言awareな正準構造＋3層静的解析の違反診断を修復提案に与え、「違反を減らす変更のみ適用」する実行時モニタを追加、EFで解消できなかった誤りの77.8%を追加解決した
- **使いどころ**：社内text-to-SQLの修復パイプライン。3ベンチ（BIRD/Spider/Mini-Dev）×3方言×6モデル構成で反復半分・トークン30%減・絶対精度最大+11.6pt、適用後の静的検出可能な退行0件
- **明日試せる最小検証**：既存EF修復プロンプトにsqlglot等の静的診断（未定義参照・スコープ・型違反）を併記し、社内誤りセット50問で修復率と反復回数を素のEFと比較（1日）
- **落とし穴**：対象は構文・構造・意味の機械検出可能な違反で、ビジネス定義の誤りは対象外（それは2610.41090の領分）。正準構造＋3層解析器の自作実装は工数。コード公開の記載なし

### [AIの心理学応用] Incongruence-Aware Evaluation of Multimodal Speech Emotion Recognition in Audio Large Language Models
- **arXiv**：[2610.40883](https://arxiv.org/abs/2610.40883) / 2026-10-29 / cs.AI, cs.CL, cs.MM, cs.SD
- **要点**：音声対話LLMの感情認識は、テキストと音声のチャネル不一致（共有VAD空間の距離をラベルフリーでスコア化、人手判断で検証）でエラー確率が上がる——3コーパス（演技・会話・自発話）共通で、正解感情を統制後も残る。教師分類器は逆向きで、失敗は信号でなく証拠の結合にある。6つの代替スコア中ただ一つ全コーパスでエラーを予測
- **使いどころ**：音声インタビュー・CMプリテストの感情分析導入前の品質ゲート——不一致スコアで「読みが当てにならない区間」を除外。コード・データ・プロンプト公開

### [エージェント・ハーネス設計] Does Showing Agents the Privilege of Their Tools Reduce Over-Privileged Tool Selection?
- **arXiv**：[2610.40975](https://arxiv.org/abs/2610.40975) / 2026-10-29 / cs.CR
- **要点**：ツール説明に権限クラスとコストを書くだけで、過剰権限ツールの選択が最大19.3pt（50%）減。無関係メタデータを同形式で書いた対照では効かない。ただし情報単独では昇格を遅らせるだけで、最小権限指示と併用すると標準ツールだけで完結する率が18.8%→51.1%（ToolPrivBench 544シナリオ×8モデル×5条件）
- **使いどころ**：社内エージェントのツール定義——説明文の追記だけで導入できる、権限強制機構の安価な補完

### [エージェント・ハーネス設計] "Shall We Approve?" Consequence-Aware Approval for Autonomous Coding Agents
- **arXiv**：[2610.40753](https://arxiv.org/abs/2610.40753) / 2026-10-29 / cs.CR, cs.AI
- **要点**：シェルコマンドの承認判断を、テキスト（リクエスト文・コマンド文）でなく、スナップショットサンドボックスで事前実行した「観測された効果」の有界レポートに基づかせるCaper。有害結果率6.7%（既存6システムの最小は14.8%）、呼ばれるツール内に隠された有害挙動（自作ベンチYoloFS-Ext）でも7.8% vs 最小35.3%、安全な双子タスクの誤ブロックは1.0%
- **使いどころ**：コーディングエージェントの実行承認フロー——「このコマンドは何をするか」を推測でなく実行観測に置き換える。有害結果率をKPIに
