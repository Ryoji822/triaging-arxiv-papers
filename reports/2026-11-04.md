# arXiv 論文トリアージレポート
**対象期間：2026年11月2日〜2026年11月4日**

## 今週の要点
- 「数字が正しく見えても、測っているものを疑え」が今週の一つの流れ。エージェントリーダーボードは採点・集計のコードが静かに壊れて順位を動かし（2611.04399）、text-to-SQLは実行が成功したまま「計算の選択」を黙って1解釈に決めている（2611.04318）。
- 実運用側では、Tencentの商用LLMコーチが「変更なし再実行で失敗の38.4%が回復する」ことを示した。再実行ノイズを差し引かない改善判断は、実際には出荷15改訂のうち14件が根拠を欠いていた（2611.04772）。
- 動画生成のボトルネックはレンダリングから意味制御に移った。Kling（快手）がキャプション=意味契約、2段報酬モデル、テキストだけでの候補スクリーニングという「理解スタック」の設計知見を公開（2611.04916）。
- 多言語クリエイティブでは、画像内テキストの機械翻訳（看板・パッケージの文言差し替え）が学習なしパイプラインで学習ベース超えまで来た（2611.04303）。

### [セマンティックレイヤーとオントロジー運用] Text-to-SQL Models Make Choices Without Saying So
- **arXiv**：[2611.04318](https://arxiv.org/abs/2611.04318) / 2026-11-03 / cs.DB
- **何が新しいか**：従来の曖昧性ベンチ（AmbiQT/AMBROSIA）はスキーマや語彙の曖昧さだけを測り、「行数かdistinctか」「同順位を全部返すか」といった計算の選択が黙って決められる現象は測ってこなかった。SpecBridgeは「選択だけが異なる3リクエスト」で計算と報告を分離し、黙秘ミスの72-94%は報告の失敗で計算はできていること、BIRDの約1割の質問は解釈で答えが変わることを示した。緩和はモデル強化でなく「開いた選択か決めてから各解釈を別コールで答える」2相法で解釈網羅+29〜63pt。
- **使いどころ**：分析レポート自動化（text-to-SQLエージェント）の誤答・黙秘の検出と低減。数値の「もっともらしさ」に頼る報告プロセスの品質ゲート。
- **明日試せる最小検証**：社内text-to-SQLログから集計系の質問を20件抽出し、SpecBridge式の3変種（オープン/解釈A明示/解釈B明示）を1モデルに投じて黙秘率を測る。半日〜2日。コード・データ・全応答が公開済み（github.com/Xyc-arch/specbridge-artifact）。
- **落とし穴**：「想定を述べよ」とプロンプトで指示しても黙秘は残る（本文実測）。判定にjudgeモデルを使う。日本語の計算選択語彙の分布は未検証。

### [エージェント・ハーネス設計] TactiNavi: Serving and Revising an LLM Game Coach with Explicit Strategy Conditions
- **arXiv**：[2611.04772](https://arxiv.org/abs/2611.04772) / 2026-11-03 / cs.AI
- **何が新しいか**：状態依存の正しさを持つLLMエージェントで、アドバイスの適用条件を散文でなく3値（真/偽/不明）の明示的アーティファクトにして、オフラインコンパイル→実行→診断→リリースの全段階で同じオブジェクトを使い回した実運用報告。条件付き知識パッケージで正答率57.9%→82.0%（CI [16.4, 31.7]）。さらに「変更なし再実行で失敗ターンの38.4%が回復する」null modelをリリース判定に組み込み、実際に出荷された15改訂ユニットのうち基準を通ったのは1件だけだったことを示した。
- **使いどころ**：顧客状態・版数で正解が変わるLLMプロダクト（コーチング・レコメンド・コンサル系）のサービング設計と、プロンプト・知識改修の効果検証。改善率の過大申告防止。
- **明日試せる最小検証**：既存エージェントの失敗トレース20件を変更なしで再実行し、何%が自然回復するか（ノイズフロア）を測る。半日。回復率が高ければ、過去の「直った」判断を見直す。
- **落とし穴**：実運用ログの回顧的評価で、ランダム化比較ではない。状態スキーマと条件の初期設計コストがかかる。単一ゲームドメインでの検証で、一般化は自社で確認が必要。

### [広告クリエイティブ生成] Behind Video Generation: Observations and Insights on Multimodal Understanding from Kling
- **arXiv**：[2611.04916](https://arxiv.org/abs/2611.04916) / 2026-11-03 / cs.CV
- **要点**：動画生成のボトルネックは描画でなく意味制御に移った。Kling（快手）が世代間の開発知見を整理：キャプションは記述密度を最大化する「意味契約」として設計し参照バインディングを明示化、報酬モデルは説明可能な一般RM＋高速な意思決定RMの2段構え、テキストエンコーダの信頼性は言語能力でなく知覚訓練から来る、end-to-end訓練の前にテキストだけで候補を絞れる。
- **使いどころ**：動画クリエイティブ生成のパイプライン設計（プロンプトエンハンス・キャプション設計・自動評価）の方針決定。

### [広告クリエイティブ生成] FlowTranslator: Training-Free In-Image Machine Translation with Flow-Based Editing
- **arXiv**：[2611.04303](https://arxiv.org/abs/2611.04303) / 2026-11-03 / cs.CV
- **要点**：画像内テキストの機械翻訳（看板・パッケージ・バナー）を、OCR+LLMで翻訳プロンプトを生成しT2I拡散編集に流す学習なしパイプラインで実現。軌道制御2つ（領域の結合解除・変位増幅）で訳語の正確性と自然さを制御し、学習ベースの強ベースライン（UniTranslator）をBLEU/COMETで上回る。
- **使いどころ**：多言語クリエイティブ展開のローカライズ工数削減（撮影し直し不要の文言差し替え）。

### [エージェント制御] Where Is the Truth When AI Agents Disagree? Dependence-Aware Belief Propagation for Unsupervised Truth Discovery
- **arXiv**：[2611.04805](https://arxiv.org/abs/2611.04805) / 2026-11-03 / cs.AI
- **要点**：同一ベースモデルの派生エージェントは誤りが相関するため、古典的真実発見・クラウドソーシング推定量は合意ブロックを reward して多数決を下回る。相関ブロックを「約1票」と数える変分推論（BP-TD）でラベルなし多数決超え（MMLU 0.716 vs 0.624）。ただしラベル20問あれば単一最良エージェントの選択が全アグリゲータに勝つ。
- **使いどころ**：複数LLMの意見統合（アンサンセル）設計。同系モデルを並べることの無意味さの定量的根拠。

### [エージェント制御] Silent Instrument Errors Reorder Agent Leaderboards

- **要点**：公開エージェントリーダーボード2つ（HAL/tau2-bench）の計装を公開成果物だけから監査し、採点されない会話終了、コスト二重計上、graderの行動の軌跡混入、評価器更新での順位変動など5つのサイレントな計装エラーを発見（3件はメンテナが5週間以内に確認）。採点率の報告・ルートスパンからの集計・行動の出所タグ・評価器バージョン固定+再採点diffを提案。
