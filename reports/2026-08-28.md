# arXiv 論文トリアージレポート
**対象期間：2026年08月26日〜2026年08月28日**

## 今週の要点
- **LLMジャッジの「監査方法」自体が統計検査の対象になった**。有界な評定スケール上の二重差分（DiD）は、共通の厳格シフトだけで交互作用を「製造」できる——事前登録実験での唯一の有意な効果が79-85%は選好ゼロで再現されるという反例つき（2608.27309）。LLMジャッジを評価に使う全工程の設計前提が揺れる。
- **クリエイティブ自動検品が「固定スコアラ」から「指示ごとのルーブリック生成」へ移行**。9Bオープンモデルが専用報酬モデル最良を超え、Gemini 3.1 Pro級の商用ジャッジに匹敵（2608.26956、EMNLP 2026・公開）。軸別スコアが残るので判定根拠も残る。
- **エージェント・セキュリティは攻撃の標的が「ハーネスの文脈組み立て」に移動**。低権限コンテンツが指示レベルを昇格する経路（2608.27299）は権限レビューを貫通。防御側は宛先Allow-list・能力分離・情報フロー制御へ収斂しつつあるが、既知ラインの延長で今回の差分は中程度。
- 長尺動画生成は「記憶の設計」が主戦場になりつつあるが、今回は学習不要の局所改善が並ぶ程度（2608.26902 / 2608.26671）。

### [データ分析] Difference-in-Differences on a Censored Rating Scale Can Manufacture an Effect（事前登録LLMジャッジ監査での証拠）
- **arXiv**：[2608.27309](https://arxiv.org/abs/2608.27309) / 2026-08-27 / cs.CL
- **何が新しいか**：従来のLLMジャッジ監査は「マッチ条件間の二重差分で交互作用が有意ならバイアス証明」と扱ってきたが、有界評定スケールでは各条件のcensoring率が異なるため、両極を同方向に動かすだけの共通シフト（選好ゼロ）でも交互作用が製造されることを閉形式で示した。事前登録・密封した990コールの監査で、主要エンドポイントはnull（+0.085、p=0.684）なのに唯一の有意な交互作用（+0.378、p=0.002）を「選好ゼロ構成」が79-85%再現する生きた反例を実証。診断法は監査が既に持つ評点から計算できる。
- **使いどころ**：調査・効果検証工程のLLMジャッジ監査設計。バイアス推定の妥当性担保（誤ったバイアス認定・バイアス否定の両方の誤りを防ぐ）。
- **明日試せる最小検証**：社内のLLMジャッジ比較評価（クリエイティブ採点・調査コーディング等）から、評点が天井/床に張り付いた項目の割合を数え、本論文の「ピン留め極の割合」診別を1つ適用してみる（半日・既存評点データのみ）。
- **落とし穴**：有界評定スケールのDiD読み取り限定の話（順序→間隔扱いの問題は別途残る）。単一ジャッジ・教育学ルーブリックでの実証で、外部妥当性は著者自身が限界として明示。ライセンスCC BY-NC-ND（社内利用は可、再配布注意）。

### [広告クリエイティブ生成] RubricRM: Generative Reward Modeling via Dynamic Rubrics for Image Generation and Editing
- **arXiv**：[2608.26956](https://arxiv.org/abs/2608.26956) / 2026-08-27 / cs.CV（EMNLP 2026 Main採録）
- **何が新しいか**：従来の視覚報酬モデルは単一スカラーか固定基準で、指示による必要評価軸の違いに追従できなかった。RubricRMは入力ごとに評価軸・重み・採点基準をルーブリックとして生成してから軸別採点し、Qwen3.5-4B/9Bベースで専用報酬モデルの最良（UnifiedReward-Flex等）を一貫して上回り、Gemini 3.1 Pro級の商用MLLMジャッジに匹敵（Gen: 84.5 vs 84.8 / Edit: 85.6）。モデル・データ（31.8K+30.7K）・コード公開。
- **使いどころ**：クリエイティブ制作の自動検品・差し替え対の自動A/B評価。判定根拠（軸別スコアと重み）が残るため検品レビュー工数を削減し、ジャッジAPIコストを自社GPU/低額APIに置換できる。
- **明日試せる最小検証**：過去のクリエイティブ差し替え対（改変前後）20組にRubricRM-Gen-9B／Edit-9Bを回し、人間の採用判定との一致率を既存MLLMジャッジと比較する（半日・GPU1枚）。
- **落とし穴**：教師がGemini 3.1 Proで、教師バイアスの継承を著者自身が警告（対象分布での監査を推奨）。静的画像限定（動画不可）。ペア比較専用で絶対スコア付けではない。報酬モデルとして最適化に使うとバイアスが増幅されうる。

### [データ分析] A Table Is Worth 64 Tokens: Pixel-level Compression for Multi-Table Document Question Answering
- **arXiv**：[2608.26949](https://arxiv.org/abs/2608.26949) / 2026-08-27 / cs.AI
- **何が新しいか**：従来の光学コンテキスト圧縮は表理解への影響が不明だった。本論文は「関連表の特定は高倍率ダウンスケール画像で十分、採点・推論はネイティブ解像度が要る」という非対称を5VLM×2ベンチで実証し、2段階方式（低解像度で関連表を選び→ネイティブ解像度で推論）で長文ドキュメントQAのトークン41%削減と精度+7ptを学習なしで達成した。
- **使いどころ**：調査工程の表だらけの資料（市場データ・クライアント報告書）のRAG/QAパイプライン。トークンコスト-41%・精度+7pt。
- **明日試せる最小検証**：表5枚以上を含む社内ドキュメント3本で「ネイティブ1段 vs 2段階」を比較し、トークン消費と正答率を記録する（半日・既存VLM APIのみで再現可）。
- **落とし穴**：表を画像化できるフローが前提。ダウンスケールしすぎると読めなさを補う長い推論トレースで節約が相殺される（本論文の中心知見でもある）。

### [エージェント・ハーネス設計] When Context Gets Root: Privilege Escalation in LLM Harnesses
- **arXiv**：[2608.27299](https://arxiv.org/abs/2608.27299) / 2026-08-27 / cs.CR, cs.SE
- **要点**：モデル側防御の指示階層（instruction hierarchy）に対し、ハーネスが各呼び出しの文脈を組み立てる際に低権限コンテンツをより高い指示レベルに持ち上げる「指示特権昇格」を提示。6つのコーディングエージェントハーネスで機密性・完全性・可用性・RCEの13目標を全達成し、自動権限レビューモードでも全達成、永続ゴールや定期タスク経由でも再現。
- **使いどころ**：社内エージェント運用のセキュリティ監査——信頼できない素材（Web・ドキュメント）がシステム/開発者指示領域に連結される経路の棚卸し項目として即追加できる。

### [エージェント・ハーネス設計] Zero-Shot Self-Orchestration with Ledger-Based Control
- **arXiv**：[2608.26480](https://arxiv.org/abs/2608.26480) / 2026-08-27 / cs.MA, cs.AI, cs.CL, cs.SE
- **要点**：manager-worker足場の効果を9モデル（5オープン+4クローズド）×最新100難問でペア比較。利得はモデル条件付き（+30.4〜-9pt）で、マネージャーはトークン請求を約3倍にするが、精度1ptあたりのコストは大型モデルへの乗り換えより安い（GPT-5.6+マネージャー$11.71 vs Fable 5単体$61.11/100問）。利得機構は文脈管理と問題分解に帰着。
- **使いどころ**：コーディングエージェントのコスト設計——「モデル増強より先にマネージャー足場を試す」という意思決定規則の定量的根拠。

### [エージェントの長期記憶] GraphMemix: Query-Aware Evidence Forests for Long-Term Multimodal Agent Memory
- **arXiv**：[2608.26983](https://arxiv.org/abs/2608.26983) / 2026-08-27 / cs.AI
- **要点**：長期記憶の組織化を「高価なオフライン要約 vs ナイーブな埋め込み類似」の二択から、クエリ依存の証拠森構成（組合せ最適化・証拠予算制約付き）へ再定式化。多視点シード拡張と証拠効用/活性化コストの分離で、4つのマルチモーダル記憶ベンチで精度×ライフサイクルコストの新しいパレートフロンティア。
- **使いどころ**：記憶持ちエージェント運用の検索設計——クエリ時選択に寄せることでオフライン要約の保守コストを回避する構図。
