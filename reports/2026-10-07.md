# arXiv 論文トリアージレポート
**対象期間：2026年10月5日〜2026年10月7日**

## 今週の要点
- エージェント評価の焦点が「どの数字が出たか」から「その数字を信じられるか」に移った。記録済みベンチスコアに4属性の事後検証をかけると合格の22.6%しか全通過せず、18-46%のタスクが5回の再実行でスコア帯を維持しない（2610.07274）。6主要ハーネスのセキュリティ機構をON/OFFで比較した初の体系的データも到着（auto-approveで攻撃成功率29.2%→95.6%、2610.07639）。導入検収は「ベンチ表の並べ替え」から「検証可能な証拠の棚卸し」へ。
- 販促施策の増分測定に新しい識別戦略。Airbnbのギフトカード研究は「処置（カード所持）は使われた瞬間にしか観測されない」というクーポン・ポイント施策共通の構造問題を、観察ログ＋小規模実験のデータ融合で解き、自己贈与セグメントが最も増分的という反直観的結果を出した（2610.08558）。
- クリエイティブ生成の実務ボトルネックが画質から「仕様準拠」へ。HEX数値色指定がVAE潜在の色部分空間steeringで81%に到達（2610.07072）、権利物・unsafe概念の消去が重み変更なしで構成的プロンプトに耐えるようになった（2610.07337）。
- 長期記憶の設計指針は逆説的に「深く作るな、広く渡せ」。検索構造の深さに単調な利得はなく、文脈幅1K→4Kで精度+10-18pt、8-16Kでプラトー（2610.08300）。

### [データ分析] Measuring Gift Card Program Incrementality via Causal Data Fusion
- **arXiv**：[2610.08558](https://arxiv.org/abs/2610.08558) / 2026-10-06 / econ.EM, stat.ME
- **何が新しいか**：販促施策の増分測定は「大規模RCT（配布コストが高すぎる）」か「観察データ（処置が購買時にしか観測されず識別不能）」の二択だった。処置censoringのある大規模観察ログと別母集団の小規模実験を、条件付き相対処置効果の移転可能性という1つの弱い仮定だけで融合すれば識別・推定できることを示した。
- **検証済みの数字**：Airbnb全米4チャネル（150以上の共変量で調整）でB2B・Retail Onlineが増分positive（IR/IC 0.20-0.22、B2Bは有意）、First-Partyはほぼ中立から負。自己贈与セグメントはIR 0.35-0.50と最も増分的（95%CIがゼロを除外）。共変量非調整のnaiveベースラインは増分を大幅に過大評価。本文HTMLで確認（80ページ・9図13表、感度分析と仮定違反の議論付き。コード公開の記載なし）。
- **使いどころ**：クーポン・ギフトカード・ポイント施策の効果検証工程。incrementality ratio（IR）による配布チャネル別の予算配分見直し。
- **明日試せる最小検証**：過去の小規模テスト配布（数千人規模の実験・キャンペーン）のログと観察ログを突き合わせ、既存施策1件のIRを概算し、赤字額ベース（naive）との差を見る（2日。識別式は論文第5節の再現実装が必要）。
- **落とし穴**：移転可能性の仮定（母集団間で条件付き購買確率の比が不変）が破れるケース（時期差・地域差・受領経路の違い）を感度分析で確認する必要がある。コード未公開で自前実装。クライアントデータの結合には個人情報の取扱い規定が前提。

### [エージェント・ハーネス設計] HarnessSecurity-Bench: Do Security Mechanisms Really Protect Coding Agent Harnesses?
- **arXiv**：[2610.07639](https://arxiv.org/abs/2610.07639) / 2026-10-06 / cs.CR, cs.SE
- **何が新しいか**：ハーネスの安全性は個別攻撃の実証（スキル注入・フック攻撃）で語られてきたが、初めて40ハーネス×10機構の実装状況（確認済み実装の約半分がopt-in、クローズドソースの53%は根拠すら不明）と、6主要ハーネスの機構ON/OFFを同一タスク・決定論的オラクルで横断比較した。設定の費用便益が数字で初めて読める。
- **検証済みの数字**：6ハーネス（Claude Code、Codex CLI、Gemini CLI、gptme、Qwen Code、Copilot）×23タスク×2,500試行（81,155ツール呼び出し）。auto-approve有効化でASR 29.2%→95.6%かつutility上昇。network isolationはASR 57.1%→0.8%だがutility -24.5pt。command denylistは攻撃減とutility増を両立。本文HTMLで確認（ベンチ・プロジェクトサイト公開）。
- **使いどころ**：エージェント導入時のハーネス選定とセキュリティ設定。工程は運用。指標は攻撃成功率とタスク効率のトレードオフ（侵害リスクと生産性）。
- **明日試せる最小検証**：自社で使っているハーネスの auto-approve / sandbox / denylist 設定を棚卸しし、公開ベンチの23タスクから該当攻撃面を3つほど現行設定で流してASRを測る（半日〜2日、Docker環境）。
- **落とし穴**：攻撃評価は単一モデル（GLM-5.2）でモデル別のASRは変わる。23タスクは攻撃面のサンプルで網羅ではない。denylistの整備は運用コストが継続する。

### [エージェント制御] A Trust Layer for Agent Evaluation
- **arXiv**：[2610.07274](https://arxiv.org/abs/2610.07274) / 2026-10-05 / cs.AI
- **何が新しいか**：エージェント検収の知見は「完了主張を疑え」（2608.24979）など個別の警告にとどまっていた。記録済みスコア自体に4属性（グレーダ再現・計算の追跡可能性・完了主張の整合・再実行安定性）をpost-hoc検証する枠組みで、単発スコアのどこが信用できないかを分解して測れるようにした。
- **検証済みの数字**：Agents' Last Exam 108タスク×5モデル。合格の22.6%（95% CI 15.0-32.6）しか4チェック全通過せず。計算の追跡できない合格はモデル間で10倍差（1/22〜10/21）。18-46%のタスクが5回再実行でスコア帯を維持せず、合格側の再実行は記録より低い方向（平均が隠す符号付きの差）。本文HTMLで確認（手検証・κ・CI付き。コードはacceptance後公開）。
- **使いどころ**：エージェント/モデル選定の検収工程。単発スコアの代わりに「ベリファイド合格率」「band安定率」を比較指標に。
- **明日試せる最小検証**：自社評価タスク10個を同一設定で5回再実行し、スコア帯の安定率を測る。1回で合格/不合格が入れ替わるタスクの割合が出る（2日、APIコスト5倍分）。
- **落とし穴**：コード未公開（acceptance後）でD1-D3の再現は自前実装。再実行検証はコスト5倍。ALE依存の評価で、自社タスクへの一般化は適用作業が必要。

### [広告クリエイティブ生成] On Color Alignment in VAE Latent Spaces and Its Applications
- **arXiv**：[2610.07072](https://arxiv.org/abs/2610.07072) / 2026-10-05 / cs.CV
- **要点**：T2IモデルのVAE潜在空間に輝度＋反対色の色部分空間がSD1.5からFLUX.2まで一貫して存在し、それを回復した潜在steering（色名プロキシ＋残差変位のMLP）で数値色指定の精度が飛ぶ。GenColorBench細粒度系（CSS3/X11）でFLUX 81.20%（従来最良NumColor 51.96%）、22人の2AFC知覚実験でも優位。彩度制御・色転送も同じbasisで可能。
- **使いどころ**：クリエイティブ制作のブランドカラー厳守（HEX/RGB指定の再現精度、色リテイク工数の削減）。プロンプトでは届かなかった仕様どおりの色が、学習ほぼなし・重み不改変で手に入る。

### [広告クリエイティブ生成] Compositional Concept Erasure in Text-to-Image Diffusion Models via Hierarchically Grounded Semantic Surgery
- **arXiv**：[2610.07337](https://arxiv.org/abs/2610.07337) / 2026-10-05 / cs.CV
- **要点**：T2Iからの概念消去（著作権・unsafe・指定語）は重み編集型（対象ごとに再訓練・チェックポイント改変）かtraining-freeかの二択で、後者は構成的プロンプトで消去対象が上位語経由で呼ばれたり修飾語が残存物に移動したりして失敗していた。階層的スパングラウンディング＋早期デノイジングでの属性結合修正で、階層的回避を29.54→10.02に減らし属性漏出をほぼ半減（学習なし・重み不改変）。
- **使いどころ**：クリエイティブ制作の権利物・unsafe概念混入対策（ブランドセーフティ）。モデルを改変せず運用パイプラインに足せる。

### [AIの心理学応用] The Failure Is in the Readout: Fine-Grained Emotion Recognition Benchmarks Measure Elicitation, Not Perception
- **arXiv**：[2610.08162](https://arxiv.org/abs/2610.08162) / 2026-10-06 / cs.CV, cs.CL
- **要点**：細粒度感情認識（40カテゴリ）でのVLMの低スコアは知覚能力ではなく「生成で答える」読み出しの問題だった。logitsからカテゴリ毎の二値照会で読むと、11モデルすべてが専門家一致（κ_w=0.468）を超え（0.507-0.586）、3モデルはfine-tuned専用モデル（EIF）を上回る。実写真（FACES）でも10モデル中6つが改善。しきい値二値化だと利得が消える＝確率の勾配情報が本体。
- **使いどころ**：表情ベース感情計測を調査・クリエイティブ事前評価に使う際の計測妥当性。fine-tune不要・APIのlogprobだけで実装できる。

### [セマンティックレイヤーとオントロジー運用] QRAKEN: Natural Language Questions as an Interface for Knowledge Graphs
- **arXiv**：[2610.08095](https://arxiv.org/abs/2610.08095) / 2026-10-06 / cs.AI, cs.CL
- **要点**：text-to-SPARQLは未知グラフで「文法的に正しいが実データモデルを誤解する」クエリを出す。スキーマでなく取得された多ホップパターン・条件頻度・パス条件付きリテラル例を蒸留したTTQLで生成をグラウンドし、決定論チェックの修正ループを足すと、CK25（Text2SPARQL）で厳密F1 0.64-0.65（最強参加者比+30-32%）、35Bローカル4bitモデルでも最強参加者並み。SHACLスキーマ露出より+64%。
- **使いどころ**：社内ナレッジグラフ・RDFデータへの自然言語アクセス精度改善（学習なし、オンラインはコンパクトな蒸留物を注入するだけ）。

### [エージェント制御] Verifying Coordination in Parallel Coding Agents: NP-Bench and a Scheduling Planner
- **arXiv**：[2610.07261](https://arxiv.org/abs/2610.07261) / 2026-10-05 / cs.AI
- **要点**：同一コードベースで並走するコーディングエージェントの衝突（二重書き換え・契約変更の食い違い）は「検出して警告」のリアクティブ協調ではエージェント速度に間に合わない。作業スコープの事前分割とproducer→consumer順のマージ・スケジューリングに再定式化すると、clean integration 1/9→9/9、マージコンフリクト13→0。ネガティブ結果（長いコンテキストへのファクト注入は救済にならない）も実務的に有用。
- **使いどころ**：複数エージェント並列運用の編成設計。統合成功率と無駄編集（トークン）の削減。

### [エージェントの長期記憶] Memory Depth and Reconstructed Context Width: A Controlled Evaluation of Hierarchical Retrieval
- **arXiv**：[2610.08300](https://arxiv.org/abs/2610.08300) / 2026-10-06 / cs.CL
- **要点**：長期会話記憶で提案されてきた深い構造（階層・グラフ・因果リンク）の深さ（D1-D4）には単調な利得がなく、答えモデルに渡す文脈幅を1K→4Kに広げるだけで精度+10.11〜17.98pt。8-16Kでプラトーし、それ以上は正解あたりトークンが増えるだけ。オラクル条件は68-71Kの全アーカイブで品質を維持。
- **使いどころ**：記憶システム設計の優先順位付け——構造の複雑化より大きく一貫した文脈ブロック。トークンコスト対精度の実測根拠。
