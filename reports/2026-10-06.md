# arXiv 論文トリアージレポート
**対象期間：2026年10月4日〜2026年10月6日**

## 今週の要点
- ハーネス研究の焦点が「性能を出す構成」から「動き続けるコードの品質」へ移った。ハーネスのテスト充足性の初実証（LLM出力を処理するコードが半分以下しかカバーされていない、2610.04921）、リポジトリガバナンス違反43.1%の測定（2610.06193）、そして本番Claude Code/Codexへの多段階注入攻撃とその実行直前遮断（2610.05163）。
- マルチエージェント化の安全設計に具体的研究が着いた。単一エージェント向けCapability系防御（CaMeL）の保証は委任チェーンで合成しないことの実証と修正プロトコル（2610.05640）、プロバイダが自社コンテンツだけでプロアクティブエージェントを操作する新攻撃面（2610.05266）。
- 生成運用の経済性：動画モデルの嗜好×予算ルーティング（コンセンサスすら個人のfavoriteと34-55%しか一致しない、2610.05896）、図の縦横比転用のエージェント自動化（2610.06852）。
- シリコンサンプリングの土台点検：対話データセット自体が持つ「署名」がユーザーモデルの評価結論まで伝播する（2610.05534）。

### [エージェント・ハーネス設計] Complex Agents, Shallow Tests: Demystifying and Enhancing Test Adequacy of Agent Harness in the Wild
- **arXiv**：[2610.04921](https://arxiv.org/abs/2610.04921) / 2026-10-04 / cs.SE
- **何が新しいか**：ハーネス研究は足場・ツール・記憶の構成最適化に集中し、ハーネス自体のソフトウェアテストは誰も測ってこなかった。初の実証で、LLM出力を処理・解釈するハーネスコード（LDH）が行・分岐とも半分以下しかテストされていない実態を示し、ハーネス契約を明示したテスト生成HarnessTesterで実運用システムからバグを大量検出した。
- **検証済みの数字**：汎用テスト生成のSOTA比で行/分岐カバレッジ+75.95%/+84.76%、変異スコア+69.89%。広く使われるエージェントシステム（OpenClaw等）でバグ122件検出（88件が新規・69件が開発者確認済み）。absページで確認（コード公開の明記なし）。
- **使いどころ**：社内エージェントツールのQA工程。ハーネス起因の障害件数とLDH部分のテストカバレッジ。
- **明日試せる最小検証**：自社ハーネスのLLM出力パース・再試行・ツール分岐のコードを洗い出し、異常系LLM出力（切断されたJSON・空配列・存在しないツール名）を想定したモックテストを5ケース書いて、現在どれが落ちるか確認する（1日）。
- **落とし穴**：対象はPython製OSSハーネス中心で、自社スタックへの適用は移植作業が必要。テスト生成自体がLLM依存で偽陽性のトリアージ工数が乗る。再現物の公開明記なし。

### [エージェント・ハーネス設計] Blocking at the Boundary: Auditing Long-Horizon Agents against Staged Prompt Injection
- **arXiv**：[2610.05163](https://arxiv.org/abs/2610.05163) / 2026-10-04 / cs.CR
- **何が新しいか**：従来の注入対策は入力スクリーニングか実行後の評価で、多段階ワークフロー内を伝播し後段の重要アクションを改変する「staged injection」の介入点を特定できなかった。結果をもたらす各行為の実行直前にpending actionへPass/Block判定を下す「境界行為監査」を定式化し、アクションを構成要素に分解して値と判断の出所を追跡する学習なし監査人PAAを提示した。
- **検証済みの数字**：Claude CodeとCodexのネイティブ実行環境で自動攻撃生成（8ワークフロー・7攻撃目標・6注入経路）し、479ペア3,112ユニットのベンチを構築。fail-open採点でPAAはBlock想起86%・誤遮断6-8%（従来のARGUSは44-47%・16-33%）。全ペア比較の95%CIが零を排除。コード・データ公開（29ページ・10図・20表）。
- **使いどころ**：コーディング/業務エージェント導入時のセキュリティ設計。攻撃遮断率と誤遮断率（業務妨害リスク）の両建て指標。
- **明日試せる最小検証**：自社ワークフローで外部コンテンツを読み込むツール呼び出しを1週間分抽出し、「各引数の値をどこから得たか」を実行ログから追跡できるか（=出所追跡監査の必要前提が整っているか）確かめる（半日）。
- **落とし穴**：監査にLLM（Claude Sonnet 5）を使うためツール呼び出しごとにコストとレイテンシが乗る。fail-open前提のスコアで、fail-closed運用では誤遮断の業務影響を別途測る必要がある。攻撃ベンチは自動生成パイプライン由来で網羅は保証されない。

### [広告クリエイティブ生成] TasteRoute: Personalized Routing for Video Generation
- **arXiv**：[2610.05896](https://arxiv.org/abs/2610.05896) / 2026-10-05 / cs.CV
- **何が新しいか**：生成モデルの選定は「どのモデルが平均で良いか」の比較だったが、嗜好の根本的な異質性（他アノテータのコンセンサスですら各個人のfavoriteと34-55%しか一致しない）を測定し、リクエスト＋ユーザー嗜好＋予算の3入力でモデルを経路する枠組みに選定問題を転換した。
- **検証済みの数字**：T2V・I2V両設定で強い単純ベースラインと競争しつつ平均生成コストを削減（予算上限が高いほど節約が増大）。多モデル比較・品質判定・嗜好ランキング・ユーザープロファイル信号を含むTasteRoute-3kデータセットを公開。
- **使いどころ**：動画制作のモデル選定・運用工程。生成コスト（円/本）と初回採用率（選好一致率）。
- **明日試せる最小検証**：過去に複数モデル案を比較した制作レビュー履歴があれば、レビュアー間・多数決と各個人の一致率を集計して自社の嗜多多様性を測り、TasteRoute-3kの分布と比べる（半日〜1日）。
- **落とし穴**：主張は「単純ベースライン並みの精度でコスト削減」が主で精度向上ではない。嗜好プロファイルの構築には個人データの取扱い（同意・保持期間）が必要。嗜好分布が自社と異なれば再調整が必要。

### [エージェント・ハーネス設計] Who Is Your Agent Serving? Provider-Side Indirect Prompt Injection in Proactive Agents
- **arXiv**：[2610.05266](https://arxiv.org/abs/2610.05266) / 2026-10-04 / cs.CR
- **要点**：外部プロバイダは自社対象に関連するコンテンツだけを制御すれば、プライベート文脈へのアクセス・エージェント侵害・追加権限なしに、良性のプロアクティブエージェントを操作できる（推薦の誘導・ユーザー文脈の動員・採用摩擦の低減の3機構）。3環境×6ユーザーモデルの全組合せで対象承認率が上昇し最大+77.4pt。多ターンでは最終承認がなくてもユーザーの制約への応答を歪め続ける。
- **使いどころ**：エージェント経由マーケティングのリスク評価とクライアント向け規範策定。GEO・ステルスマーケティング規制の観点での査察項目。

### [エージェント・ハーネス設計] Can CaMeLs Talk? Securing Multi-Agent Systems Against Indirect Prompt Injection Attacks
- **arXiv**：[2610.05640](https://arxiv.org/abs/2610.05640) / 2026-10-05 / cs.MA
- **要点**：単一エージェント向けCapability系防御CaMeLの保証は、エージェントがエージェントをツールとして呼ぶ階層構成では合成しない（全構成員がCaMeLでも、非信頼データが下流で信頼指示として再解釈される攻撃を構成）。信頼指示と非信頼データのチャネル分離をエージェント間通信に拡張したmulti-CaMeLでASR 12.9%→0.0%。utility低下はモデル能力が上がるほど縮小。
- **使いどころ**：マルチエージェント導入時のセキュリティ設計原則（委任連鎖での出所保持）。エージェント間通信のプロトコル要件定義。

### [マーケティング調査] Dataset Signatures in Human-LLM Interactions and User Modeling
- **arXiv**：[2610.05534](https://arxiv.org/abs/2610.05534) / 2026-10-04 / cs.CL
- **要点**：人間-LLM対話データセット7種はユーザーメッセージだけで出典が分類できる「署名」を持ち、既存分類タクソノミーで次元をマッチしても残る。この署名はそのデータで学習したユーザーモデルの出力と、ユーザーモデルを介したアシスタント評価の結論まで伝播する。データセット分類器は訓練データ選択にも使える。
- **使いどころ**：シリコンサンプリング/ユーザーシミュレータ設計時のデータセット選定感度分析。合成調査の結論がデータセット選択に依存していないかの頑健性チェック。

### [広告クリエイティブ生成] One Figure, Every Canvas: Editable Flowchart Relayout via Agentic Pipeline
- **arXiv**：[2610.06852](https://arxiv.org/abs/2610.06852) / 2026-10-05 / cs.CV
- **要点**：図の縦横比転用は画像編集（延伸・極端な比率で拒否）・テキスト生成系（ハルシネーション）・パース→再描画（誤配線）がそれぞれ特徴的に失敗する。Parse/Style/Layoutの各段階に決定的制約検査+VLM批評家を置くエージェントパイプラインでContent Fidelity 68.6%（従来11.2-41.4%）、draw.io編集可能なmxGraph XMLで納品。
- **使いどころ**：資料・図解アセットの多キャンバス展開（レポート→スライド→ポスター→SMS投稿）の制作工数削減。

### [エージェント・ハーネス設計] SWE-CC: Benchmarking Repository Policy Compliance for Coding Agents
- **arXiv**：[2610.06193](https://arxiv.org/abs/2610.06193) / 2026-10-05 / cs.SE
- **要点**：コーディングエージェントは機能テストを通過しても、適用可能なリポジトリポリシーの43.1%に違反し、違反の半分近くは中間実行ステップで発生する。12リポジトリの開発ドキュメントから823の機械検査可能な原子ポリシーと決定的チェッカー、実行時挙動と成果物の両方を監査するSWE-CC（SWE-bench Verified拡張500タスク）を構築。
- **使いどころ**：コーディングエージェント導入時のPRガバナンス検収。ポリシー違反率の継続測定とCIチェック設計。
