# arXiv 論文トリアージレポート
**対象期間：2026年11月18日〜2026年11月20日**

## 今週の要点
T2IのRL事後学習の利得の9割はプロンプト非依存の固定ステアリングベクトル（LoRAの1/65のパラメータ）で再現でき（2611.26627）、報酬モデルなしの自己デノイズ対比だけでテキスト描画が向上する（CANDOR）——「重い調整の大半が安い操作で代替できる」方向が動いている。エージェントの実害の大半は攻撃ではなく日常ハザードで、ハザードを名指しする警告だけが効く（ROGUE-AI）。エージェント記憶は「量」よりモデルとの適合が決める（2611.26361）。画像編集の安全判定はテキスト側に偏り、不適切な画像本体は素通りする（2611.26569）。

## S評価（読むべき）

### [広告クリエイティブ生成] RL Post-Training in Diffusion Transformers Is Activation Steering
- **arXiv**：[2611.26627](https://arxiv.org/abs/2611.26627) / 2026-11-19 / cs.CV, cs.LG
- **何が新しいか**：従来T2IのRL事後学習はプロンプト依存の複雑な変換を学ぶと考えられていたが、凍結ベースモデルに全プロンプト・全トークンで同一の固定ステアリングベクトル（0.29Mパラメータ、rank-32 LoRAの1/65）を足すだけで、公開RLチェックポイント6画像モデルの利得の90.0〜96.3%、動画2モデルで89.8%/111.9%が再現できる。ベクトル単独をFlow-GRPOでゼロから訓練しても元の利得を上回る（OCR 104.6%・PickScore 103.6%、25人のユーザースタディでRL済みと互角）
- **使いどころ**：クリエイティブ制作の生成モデル調整工程。公開RLチェックポイントからステアリングへの蒸留（フィッティング≤17 H100時間・報酬不要）、またはベクトル直接RLで、テキスト描画精度（OCR）と選好スコア（PickScore）を調整コスト桁違いの低さで改善
- **明日試せる最小検証**：プロジェクトページ（rl-is-steering.github.io）のレシピでSD3.5-MのFlow-GRPO(OCR)チェックポイントからステアリングをフィットし、自社商品コピー描画プロンプト50件でBase／RL済み／Steeredの3者をOCRスコア比較（1〜2日）
- **落とし穴**：RL事後学習の利得に限定（DreamBooth等のSFTは68〜83%しか再現できず、描けない被写体の新規学習は不可）。彩度低下・多様性低下というRLの副作用も一緒に再現される。検証はSD3.5-M／FLUX.1-dev中心

### [広告クリエイティブ生成] CANDOR: Contrastive Self-Denoising Rewards for Label-Free Text-to-Image Post-Training
- **arXiv**：[2611.25457](https://arxiv.org/abs/2611.25457) / 2026-11-19 / cs.CV
- **何が新しいか**：T2Iポストトレーニングの報酬は外部RM（選好注釈やOCR検証器）前提だったが、同一ノイズ下でのプロンプトあり／なしデノイズ誤差の対数比（絶対自己信頼に混入する「画像の単純さ」の交絡をキャンセル）を唯一の報酬にするだけで、ラベルなしでテキスト描画OCR 0.626→0.704、選好・美学含む8指標すべてを改善。外部報酬で訓練済みの公開Flow-GRPOアダプタにも上乗せできる
- **使いどころ**：クリエイティブ制作のモデル自家調整工程。注釈データを用意できない軸でのテキスト描画改善、既存アダプタの選好スコア底上げ（PickScore 23.47→23.55、ImageReward 1.31→1.36）
- **明日試せる最小検証**：公開コード（github.com/jhlee0619/candor）でSD3.5-MにCANDOR報酬のFlow-GRPOを試行し、英語商品コピー50プロンプトでPaddleOCRスコアの前後比較（2〜3日、8×H100）
- **落とし穴**：検証はSD3.5-M単一ベースで一般性未確認。専用外部報酬（OCRアダプタ0.92）には届かず、GenEvalアダプタへの上乗せはGenEval自体が0.94→0.92と微減。プローブごとに無条件フォワードが倍加し学習コスト増。日本語描画の評価は自前準備が必要

### [エージェント・ハーネス設計] Replication of Agentic Security Events: Audit and Investigation (ROGUE-AI)
- **arXiv**：[2611.26553](https://arxiv.org/abs/2611.26553) / 2026-11-19 / cs.CR, cs.AI, cs.MA
- **要点**：報道されたエージェント事故を原因だけ除いた統制とともにオフライン再現するフレームワーク。108再現の89%で被害を再現し、実害72件のうち62件は攻撃者不在——エージェントは指示どおり動き、「本番サイトと共有されたDB」等の日常ハザードを見落としていた。ツール出力直後の「ハザードとその結果を名指しする警告」だけが5モデルすべてで被害を減らし、同長の無関係な注記は効かなかった
- **使いどころ**：エージェント導入前のリスク回帰テストとハーネス設計——ツール出力後のリマインダは一般論でなく具体的ハザード名と結果を書く

### [広告クリエイティブ生成] Text-Aware, Vision-Blind: How Multimodal Image Editing Systems Handle Unsafe Inputs
- **arXiv**：[2611.26569](https://arxiv.org/abs/2611.26569) / 2026-11-19 / cs.CR, cs.CV, cs.LG
- **要点**：画像編集システムの安全機構はテキスト側に偏っている。不適切な指示文はGemini 87.1%／GPT 81.6%拒否するのに、不適切な画像+中性な指示では24.2%／22.4%しか拒否しない（5,940ペア・11リスクカテゴリ・4システム）。リスクカテゴリごとの判断はシステム間で不整合で、性的内容のみ視覚感度が高い
- **使いどころ**：ブランドセーフティ検収——UGC・既存画像を編集パイプラインに通す場合、画像単体の審査を前置する

### [エージェントの長期記憶] How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents
- **arXiv**：[2611.26361](https://arxiv.org/abs/2611.26361) / 2026-11-19 / cs.AI
- **要点**：自履歴から教訓を蒸留するガイドライン型記憶の実運用報告（IBM CUGA／watsonx Orchestrate、altk-evolve公開）。適正な記憶量は記憶側でなくモデルの性質で決まる——強いモデル（DeepSeek-V3.2）は191件フルセットで+9.5pt、弱いモデル（gpt-oss-120b）は29件の選択サブセット55.4%がフル199件51.2%を上回る。高サポートのガイドラインが逆効果になる事故も記録
- **使いどころ**：エージェント運用——ガイドライン／スキルを増やす前にモデル等級別にサブセット選択を比較する

### [同僚としてのエージェント] AI-Induced Social Erosion: Using LLMs for Work Tasks Reduces Help-Seeking Intentions Towards Colleagues
- **arXiv**：[2611.25269](https://arxiv.org/abs/2611.25269) / 2026-11-18 / cs.HC, cs.CY
- **要点**：職務でのAI利用は同僚への助け求め意向を下げ、特にブレインストーミングで顕著（248名・ビネット実験・線形混合モデル）。一方で可視的なAI利用は助け求めを増やし、個人貢献者の同僚関係がマネージャーより脆弱。意図の測定であり行動の測定ではない点は限界
- **使いどころ**：社内AI利用ポリシー——AI利用の見え方を設計し、ブレスト工程はAI前段の人的議論を明示的に保護する

### [エージェント・ハーネス設計] Beyond Weight Updates: Evolving Agent Harnesses for Domain Specialization
- **arXiv**：[2611.25380](https://arxiv.org/abs/2611.25380) / 2026-11-19 / cs.AI
- **要点**：垂直領域特化を重み更新でなく、フリーズしたポリシー上のハーネス進化（GEPAによる反射的進化最適化）で行うと、重み更新の単独利得の大半をわずかな計算で回復し、両者併用が最良（Codev を SWE-bench Verified／OfficeBench／Terminal-Bench で一貫）。SFT特有の「推論連鎖の短縮化」を構造的に回避
- **使いどころ**：垂直エージェント開発——高価なRLの前にハーネスアダプタで安価に特化を試す
