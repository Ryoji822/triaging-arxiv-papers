# arXiv 論文トリアージレポート
**対象期間：2026年11月16日〜2026年11月18日**

## 今週の要点
- 生成系（T2I/T2V）は効率化・アーケテクチャ改良が多く差分的な知見は少ない日だが、**自己修正ループの失敗を「診断側」と「実行側」に分離測定した**LEDGEが例外。正しい編集指示を与えても失敗画像の6〜7割は直せない「editor gap」の定量は、検品・修正パイプラインの投資先を決める素材になる（S）
- データ基盤側は**LLM判定器の体系的な失敗モード**が2本：エンティティ統合でクラスターが大きくなるほどマッチ判定のハードルが下がる（誤マッチ+13.5〜32.3pt、Claude系も+22〜24pt）、マルチエージェント委任でワーカーが取得した矛盾ファクトがリーダーから消える。どちらも「LLMを判定器に使う運用の品質管理」という今月の大きな流れの一環
- エージェント選定・評価の実務手続き（リーダーボード順位は統計的に未解決、逐次半分化で評価コスト6.6%）と、シリコンサンプリングの属性開示監査（個人予測には実レコードほぼ不要、集団比較の差はラベル由来）など、**「測り直す」論文が目立つ**

### [セマンティックレイヤーとオントロジー運用] Growing Clusters Lower the Bar: Profile Accretion in LLM-Based Incremental Entity Resolution
- **arXiv**：[2611.22485](https://arxiv.org/abs/2611.22485) / 2026-11-17 / cs.CL, cs.DB
- **何が新しいか**：LLMエンティティ解決の分析は「判定は比較対象のレコードだけに依存する（oracle前提）」を暗黙に置いてきたが、クラスターに所属済みレコードを表示する増分設計では判定基準そのものがクラスター規模で動くことを、registry ID（フランス SIREN）をground truthに固定クエリ×ネストしたプロファイルで直接測定した。16メンバー表示で誤マッチ率+13.5〜32.3pt（6オープンモデル）、Claude Sonnet 5も+24.0pt（0.5%→24.5%）だがAUCは+0.05-0.08のみ＝弁別力でなく基準のシフト。さらにメンバー誰も単独では支持しない負例を受け入れ（OR null超え）、1回の誤統合が侵入口の他レコードの受容を上げる「雪だるま」も因果実証
- **使いどころ**：CRM統合・取引先マスタ・商圏データのERパイプライン構築。工程=データ基盤運用、指標=誤マッチ率。緩和策も実測済みで、ラベルデータで精度マッチ閾値を1つ設定すればrecall 1.3-2.1倍（LLM追加呼び出しゼロ、クラスター監査は不要）
- **明日試せる最小検証**：自社の類似名エンティティ（店舗・商標・取引先）20-30件について、表示クラスター人数を1 vs 8で変えてマッチ判定を比較しFMRの伸びを測る（半日〜2日。公開コード github.com/xuemian168/profile-accretion とFOPPAで再現するなら2日）
- **落とし穴**：効果は「1レコードが弱い証拠」（名前+市区程度）のレジームで出る。住所等で1レコード就能同定できる日本の法人データ（法人番号あり）では効果が小さい可能性を論文自身が示している（TED チェコ/ブルガリアでは非出現）。効果量の測定も17代理人以上の巨大クラスターレジーム前提

### [広告クリエイティブ生成] LEDGE: Separating Critic and Editor Failures in Text-to-Image Self-Correction
- **arXiv**：[2611.20446](https://arxiv.org/abs/2611.20446) / 2026-11-16 / cs.CV
- **何が新しいか**：T2I自己修正（VLM診断→画像編集実行）はこれまでend-to-endで評価され、失敗が診断の誤りか実行の不能か分からなかった。GenEvalの判定から正解編集指示（oracle）をコンパイルして画像とエディタを固定すると、ベースライン診断は指示の差で42.2→64.3%まで伸びる余地があるのに、**正解指示でもSD1.5の61.3%・SD3.5の67.5%の失敗は直らない「editor gap」**が残る。計数系は19%しか修復できない。oracleラベルで診断器をLoRA訓練するとGenEval 50.9→59.4%、SD1.5のみの訓練でSD3.5にも転移（72.0→76.0%）、FLUX.1 Kontext第2エディタ・独立ジャッジでも順位維持
- **使いどころ**：生成画像の自動検品・修正パイプライン設計。工程=クリエイティブ制作の検品、指標=修正成功率と手戻り工数。診断器を鍛える投資と編集器/再生成に切り替える投資の境界が数字で引ける
- **明日試せる最小検証**：自社の生成失敗画像20-30枚に正解の編集指示を手書きし（LEDGEのoracleプロトコル）、手持ち最強エディタでどれだけ直るかを測る。直らなければ再生成/人手に振るのが正当化される（半日〜2日）
- **落とし穴**：評価がGenEval検出器基準で、人手確認では利得が縮む（ネット修正 利得3.4pt vs 検出器評価9.0pt）。SD1.5/SD3.5+VAREdit/Kontext中心で、最新商用モデルのeditor gapは未測定。計数・位置系の欠陥はeditorがボトルネックで修正ループの対象に向かない

### [マーケティング調査] Necessary for What? Auditing Demographic Disclosure to LLM Synthetic Respondents
- **arXiv**：[2611.20606](https://arxiv.org/abs/2611.20606) / 2026-11-16 / cs.CY, cs.CL
- **要点**：シリコンサンプリングでパネル員の実属性レコードをプロンプトに入れる慣行を用途別に監査（米調査2件×14モデル）。個人予測には実レコードはほぼ寄与せず、集団分布推定の利得もセンサスデータや合成ペルソナで概ね代替可能。実レコードが効くのは群間比較だけだが、その差すら実際の回答者でなく「プロンプト内の属性ラベル」由来で、既知の群間差再現チェックでは検出できない。態度差は平準化・逆転しがち
- **使いどころ**：シリコンサンプリング活用時の個人情報最小化と調査設計。工程=調査設計、指標=予測精度とコンプライアンスリスク

### [エージェントの長期記憶] Instant Weight-Space Consolidation for Long-Term Memory in LLMs
- **arXiv**：[2611.20759](https://arxiv.org/abs/2611.20759) / 2026-11-16 / cs.CL
- **要点**：テキスト抽出型の記憶は構築コストが会話ごとに増え抽出誤差が蓄積するのに対し、セッションの潜在状態を1フォワードで低ランクアダプタに統合するhypernetwork（CLAM）+逐語バッファの2チャネル構成。LoCoMo/LongMemEval-S（2-7B×3モデル）で全agentic基準を1-45pt上回り、構築はLLM生成呼び・勾配ゼロでwall-clock 3-151倍速
- **使いどころ**：パーソナルアシスタント・継続利用エージェントの記憶構築コスト削減。工程=運用、指標=記憶構築時間。ただし2-7Bオープンモデル限定評価でフロンティア/API運用への直結は未検証、再現には訓練が必要

### [エージェントの長期記憶] Multi-Agent Memory Inconsistency: Where Factual Conflicts Disappear in LLM Agents
- **arXiv**：[2611.22245](https://arxiv.org/abs/2611.22245) / 2026-11-17 / cs.AI, cs.MA
- **要点**：マルチエージェント委任は矛盾する主張の取得率を上げる（50.2→68.7%）のに矛盾検出は下げる（16.2→13.2%）。ファクトが複数ワーカーに分割されるとリーダーの証拠から消え、検出は単一実行を下回る。ワーカー→リーダーのハンドオフが改善の中心的ターゲット（Harvey LAB・3モデル、証拠フロープロファイラ付き）
- **使いどころ**：調査・監査系の複数ワーカー分散エージェント設計。工程=分析エージェント運用、指標=矛盾検出率。効果量は小幅で「ハンドオフ設計を見直す」きっかけ材料

### [エージェント制御] Beyond Leaderboard Ranks: Selecting Software Engineering Agents Under Budget Constraints
- **arXiv**：[2611.21515](https://arxiv.org/abs/2611.21515) / 2026-11-16 / cs.SE
- **要点**：HALの58,197実行記録で精度-コストパレートの35ステップ中27が統計的に未解決、SWE-benchでは$34のエージェントと$171のリーダーを既存タスクでは統計的に区別できない。報告コストは標準化推定と最大11.7倍乖離。タスクコスト既知なら逐次半分化で網羅評価の6.6%の費用で選択を完結できる
- **使いどころ**：エージェント導入の選定・評価予算設計。工程=ツール選定、指標=評価コスト。SEベンチ中心だが予算制約付き選択の枠組みは他ドメインにも移植可能
