# arXiv 論文トリアージレポート
**対象期間：2026年8月9日〜2026年8月11日**

## 今週の要点
分析レポーティングの評価軸を「SQLが実行できるか」から「ビジネスの正しい数字が返るか」に置き換えた論文（Business Truth）が、ルールゲート付き 7B エージェントで 32B 直接プロンプトをコスト 71% 押下げて上回ることを事前登録付きで示した。分析パイプラインの信頼性設計に直結する一等地の論文。エージェント運用面では、足場（scaffolding）の選択が MCP/CLI のインターフェース差よりコストを 5〜28 倍支配すること（Scaffolding）、軌跡からコンテキスト障害を自動帰属し 82% を修復するフィードバックループ（TRACE）が実証され、どちらも「モデルよりハーネス」という直近の流れを補強する。動画生成はクロスショットの論理的整合（LogiShot）が 110K データとベンチマーク付きで広告ストーリーテリングに効く。A/B テスト理論では、二値アウトカムで独立割当がペア/層別より worst-case MSE 半減になるという反直観的結果（Optimal Experimental Design）が出て、層別化の暗黙前提を再検討する価値がある。

## S評価（読むべき）
### [セマンティックレイヤーとオントロジー運用] Business Truth, not SQL Accuracy: A Rule-Gated 7B Analytics Agent Outperforms a Direct-Prompted 32B Baseline
- **arXiv**：[2608.09254](https://arxiv.org/abs/2608.09254) / 2026-08-10 / cs.AI, cs.CL
- **何が新しいか**：従来は text-to-SQL の評価を実行一致（SQL が通るか）で行っていたが、本番の失敗は「2つの正当な業務定義がある」「スキーマ変更で廃止された列」「実行は通るが数字が違う」にあり、実行一致では採点できない。論文は WarehouseReliabilityBench（400タスク、正答の約半分が説明要求・棄却・差控え）と Business Truth Rate を新しい評価軸として導入し、セマンティックレイヤ由来のルールで挙動を決め、実行後の決定論的チェックで全回答をゲートする 7B エージェント QueryProof を出した。
- **使いどころ**：分析レポーティング／BI 自動化工程。誤成功（false success）を 0.754 → 0.351 に下げ、回答可能タスクで誤数字ゼロ（0/24）。コストあたり正答で 32B 直接プロンプトを 71% 下回る。
- **明日試せる最小検証**：手元の DWH で「2つの正当な業務定義が存在する質問」「スキーマ変更で列が死んでいる質問」を 10個作り、現行の直接プロンプトとルールゲート付きエージェントの誤成功率を比較する。**工数：2日**（ルールはメジャー定義の YAML と実行後チェックだけで組める）。
- **落とし穴**：80タスクの単発評価で、テンプレート族でリサンプルすると信頼区間がゼロを跨ぐ（方向は頑健、大きさはそうでもない）。ルーティング層の除去でほぼ変わらない（0.562 vs 0.537）ため、効き目の本体は決定論的レイヤ。コンポーネント個別のアブレーションは未実施。

## A評価（目を通す）
### [同僚としてのエージェント] AI-AI co-creation outperforms human pairs in creative tasks
- **arXiv**：[2608.09023](https://arxiv.org/abs/2608.09023) / 2026-08-10 / cs.CY
- **要点**：生成者−評価者の補完ロールを持つ AI-AI ペアが、単体 AI と人間ペアの両方を創造性と新規性で一貫して上回った（3課題・1,212アイデア・訓練済み評価者）。有用性は課題依存で、最も広範で社会的に複雑な課題ではロール分化が効く。人間ペアが最下位（グループ創造性の生産性損失と整合）。
- **使いどころ**：クリエイティブの初稿アイデア出し工程。アイデアの質と量を、ブレスト1セッションあたりの採用率で測れる。

### [エージェント・ハーネス設計] TRACE: TRajectory Attribution for Automated Context Engineering
- **arXiv**：[2608.09153](https://arxiv.org/abs/2608.09153) / 2026-08-10 / cs.AI, cs.LG
- **要点**：システムプロンプト・ナレッジベース・ツール説明・スキルの異種コンテキストソースについて、履歴軌跡に含まれる暗黙の不満シグナル（訂正・言い換え・離脱）を原因帰属し、CREATE と UPDATE を自動判定（96%）。60トレースで根本原因帰属 72.7%、エンドツーエンド修正成功率 82%。モデル再学習不要、コンテキスト層だけで回る。
- **使いどころ**：本番エージェントの運保守・改善工程。ログからコンテキスト不備を自動で拾い上げる。

### [データ分析] Optimal Experimental Design and Estimation when Potential Outcomes are Bounded
- **arXiv**：[2608.09812](https://arxiv.org/abs/2608.09812) / 2026-08-10 / econ.EM
- **要点**：二値など上限下限が分かるアウトカムでは、独立割当＋支持点中心化回帰（切片なし）が worst-case MSE を最小にする。層別・ペア固定効果回帰は worst-case MSE が2倍。完全無作為に対する漸近利得は小さいが、ペア設計に対しては一次の利得。
- **使いどころ**：二値コンバージョン（CVR）の A/B テスト設計。ペア/ブロック乱割で最適だと思っている前提を再検討する根拠。

### [エージェント・ハーネス設計] The Scaffolding Matters More Than the Interface: A Controlled Comparison of MCP and CLI Tool Use
- **arXiv**：[2608.08654](https://arxiv.org/abs/2608.08654) / 2026-08-09 / cs.AI
- **要点**：1つのソフトウェアタスク（プライベート git リポジトリへ6操作）を7足場×5モデルで実行し、リポジトリ状態で完了を検証。足場が支配的で、CLI 専用の2足場は MCP 対応の5足場より 5.0〜28倍安い。27B ローカルモデルは足場間でコスト139倍。MCP/CLI 比は 0.43〜29倍と不安定で、比較が実行時挙動を検証しないと未知の混入になる。
- **使いどころ**：コーディングエージェントの足場選定・運用コスト試算。インターフェース論争より足場選びが効く。

### [エージェント制御] LLM within MCP Matters: Measuring Inefficient Resource Utilization Driven by LLMs
- **arXiv**：[2608.08467](https://arxiv.org/abs/2608.08467) / 2026-08-09 / cs.AI, cs.CL, cs.IR
- **要点**：MCP サーバが指示文に埋め込んだ参照データを、検索ツールが存在するだけでクライアント LLM が無視する（24モデル中9モデルが15%未満）。検索を消すと23/24モデルが98%以上で読む＝能力欠損ではなく行動選好。3つの指示介入を組み合わせると20/24モデルで86%以上に戻るが、単独はモデル族によって逆効果。
- **使いどころ**：MCP サーバ／ホスト設計。サーバ指示をツール選択より前に置く仕組みが必要。

### [広告クリエイティブ生成] LogiShot: Logically Coherent Cross-Shot Video Generation
- **arXiv**：[2608.08820](https://arxiv.org/abs/2608.08820) / 2026-08-09 / cs.CV
- **要点**：ショット間の論理的接続と視覚的一貫性を、文脈動画の符号化と視覚メモリの2経路で担保。110K サンプルのデータセットとクロスショット論理整合ベンチマークを構築し、既存手法を一貫して上回る。モデルとデータは公開予定。
- **使いどころ**：ショートドラマ・連続型広告動画の制作工程。ショット切替での破綻を減らす。
